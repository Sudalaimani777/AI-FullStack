Day 2 Notes

In Day 1, the server was only an Express app.
In Day 2, this project connects Express with MongoDB using Mongoose.
We also use dotenv so secret values like the database URL stay inside `.env`.

1. Packages used

- `express`:
  Creates the server and handles routes like `GET /` and `POST /user`.
- `mongoose`:
  Connects Node.js to MongoDB and helps us create schemas and models.
- `dotenv`:
  Loads environment variables from `.env` into `process.env`.
- `nodemon`:
  Restarts the server automatically when we save changes.

2. Folder understanding

- `server.js`
  Main entry point. Starts Express, reads JSON, connects DB, and defines routes.
- `Config/db.js`
  Keeps database connection logic in one separate file.
- `Model/user.model.js`
  Defines the shape of a user document using a Mongoose schema.
- `.env`
  Stores `MONGO_URI`.
- `package.json`
  Contains dependencies and the `npm run dev` script.

3. Step-by-step setup flow

Step 1:
Create the Node/Express project.

Step 2:
Install MongoDB-related tools:
- `mongoose`
- `dotenv`

Step 3:
Create `.env` and store:
- `MONGO_URI=your_mongodb_connection_string`

Step 4:
In `server.js`, call:
- `dotenv.config()`
This loads values from `.env`.

Step 5:
Import and call `connectDB()`.
This connects the app to MongoDB before handling real work.

Step 6:
Create a schema and model in `Model/user.model.js`.
This tells MongoDB what a user should look like.

Step 7:
Create routes like:
- `GET /`
- `POST /user`

4. How each file works

`Config/db.js`

- Imports `mongoose`.
- Exports `connectDB`.
- `connectDB()` uses `mongoose.connect(process.env.MONGO_URI)`.
- If connection works, it prints a success message.
- If connection fails, it logs the error and stops the app using `process.exit(1)`.

Simple idea:
If the database is not connected, the app should not continue, because saving users will fail anyway.

`Model/user.model.js`

- Creates `userSchema`.
- The schema has:
  - `name`
  - `email`
  - `password`
- Exports `User` model.

Simple idea:
Schema is like a form design.
Model is like the machine that uses that design to create and save data.

`server.js`

- Imports Express.
- Imports dotenv and runs `dotenv.config()`.
- Imports `connectDB()` and runs it.
- Imports `User` model.
- Creates the app using `express()`.
- Uses `app.use(express.json())`.
- Starts the server on port `5000`.
- Has:
  - `GET /`
  - `POST /user`

Important line:
`app.use(express.json())`

Why it matters:
When we send JSON from Postman or frontend, Express converts it into `req.body`.
Without this middleware, `req.body` will be `undefined`.

5. Full request flow for `POST /user`

Imagine the client sends:

{
  "name": "Ram",
  "email": "ram@gmail.com",
  "password": "123456"
}

Now the flow is:

1.
Request comes to `POST /user`.

2.
`express.json()` reads the JSON body and puts it inside `req.body`.

3.
This line runs:
`const { name, email, password } = req.body;`

4.
A new user object is created:
`const newUser = new User({ name, email, password })`

5.
`await newUser.save()` sends the data to MongoDB.

6.
If save is successful, server sends:
- status code `201`
- success message
- created user data

7.
If something breaks, control goes to `catch` block and server sends:
- status code `500`
- `"Internal Server Error"`

6. Flow in one line

Client -> Express route -> `req.body` -> Mongoose model -> MongoDB -> response back to client

7. Real-world meaning of this project

This Day 2 project teaches how to:
- connect backend with database
- store data in MongoDB
- use environment variables
- separate code into files
- create your first model
- save user data from API request

8. Current improvement points in this code

The code works as a learning project, but in real apps we should also add:

- validation for empty fields
- email uniqueness check
- password hashing
- custom port using environment variable
- better error messages
- controller and route separation

9. Commands to run

From the `Server` folder:

- `npm install`
- `npm run dev`
