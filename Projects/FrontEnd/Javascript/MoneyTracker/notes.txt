                3. IIFE PATTERN - WHY & HOW
===============================================================================

What is IIFE?
-------------
Immediately Invoked Function Expression - A function that runs as soon as 
it's defined.

Syntax:
-------
const controller = (() => {
    // Private scope
    const privateVar = "hidden";
    
    // Public API
    return {
        publicMethod: () => {
            // Can access privateVar
        }
    };
})(); // <-- Immediately invoked


Benefits:
---------
1. Encapsulation
   - Creates private scope
   - Prevents global namespace pollution
   - Hides implementation details

2. Module Pattern
   - Clear public API through return object
   - Private variables and functions
   - Only expose what's necessary

3. Data Privacy
   - Private variables can't be accessed directly
   - Only through public methods
   - Protects data integrity


Example from Project:
---------------------
const dataController = (() => {
    // PRIVATE - Not accessible outside
    const data = { items: [] };
    const API_URL = "https://api.example.com";
    
    // PUBLIC - Accessible via dataController
    return {
        getData: () => data,
        addItem: (item) => data.items.push(item)
    };
})();

// Usage:
dataController.getData(); // ✓ Works
dataController.data;      // ✗ Undefined (private)

Async/Await Pattern:

Traditional Promise:
fetch(url)
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));

Modern Async/Await:
const fetchData = async () => {
  try {
    const response = await fetch(url);
    const data = await response.json();
    return data;
  } catch (error) {
    console.error(error);
  }
};

HTTP Methods Used:

GET - Retrieve Data:
  const response = await fetch(API_URL);
  const data = await response.json();

POST - Create Data:
  const response = await fetch(API_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ task, money })
  });

PUT - Update Data:
  const response = await fetch(`${API_URL}/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ task, money })
  });

DELETE - Remove Data:
  const response = await fetch(`${API_URL}/${id}`, {
    method: "DELETE",
    headers: { "Content-Type": "application/json" }
  });

Error Handling:
- try/catch blocks for async operations
- Check response.ok status
- Validate data before processing
- User-friendly error messages

===============================================================================
                    7. EVENT HANDLING PATTERNS
===============================================================================

Pattern 1: Direct Event Listener
---------------------------------
const button = document.querySelector('.add-btn');
button.addEventListener('click', () => {
  console.log('Button clicked');
});


Pattern 2: Named Function Handler
----------------------------------
const handleClick = (e) => {
  e.preventDefault();
  console.log('Handled');
};
button.addEventListener('click', handleClick);


Pattern 3: Event Delegation (Best for dynamic elements)
---------------------------------------------------------
const container = document.querySelector('.collection');
container.addEventListener('click', (e) => {
  if (e.target.classList.contains('fa-pencil')) {
    const listItem = e.target.closest('.collection-item');
    const id = listItem.id.split('-')[1];
    editItem(id);
  }
});


Pattern 4: Form Submission
---------------------------
form.addEventListener('submit', (e) => {
  e.preventDefault(); // Prevent page reload
  const formData = new FormData(e.target);
  processForm(formData);
});


Pattern 5: Input Validation
----------------------------
input.addEventListener('blur', (e) => {
  if (e.target.value.trim() === '') {
    showError('Field is required');
  }
});


Why Event Delegation?
----------------------
1. Performance: One listener vs many
2. Dynamic elements: Works for elements added later
3. Memory efficient: Fewer event listeners
4. Cleaner code: Centralized event handling

                    8. API INTEGRATION NOTES
===============================================================================

REST API Principles:
--------------------
- Representational State Transfer
- Uses HTTP methods (GET, POST, PUT, DELETE)
- Stateless: Each request is independent
- Resource-based URLs


HTTP Status Codes:
------------------
200 OK - Request succeeded
201 Created - Resource created
400 Bad Request - Invalid request
404 Not Found - Resource doesn't exist
500 Internal Server Error - Server error


Headers:
--------
Content-Type: Tells server what format we're sending
  "Content-Type": "application/json"

Accept: Tells server what format we want back
  "Accept": "application/json"


Request Structure:
------------------
fetch(url, {
  method: 'POST',           // HTTP method
  headers: {                 // Request headers
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(data) // Request payload
});


Response Handling:
------------------
const response = await fetch(url);

// Check if request succeeded
if (!response.ok) {
  throw new Error(`HTTP error! status: ${response.status}`);
}

// Parse JSON response
const data = await response.json();


Error Handling Strategy:
------------------------
try {
  const response = await fetch(url);
  
  // Network error check
  if (!response.ok) {
    throw new Error('Network response was not ok');
  }
  
  const data = await response.json();
  
  // Data validation
  if (!data || !Array.isArray(data)) {
    throw new Error('Invalid data format');
  }
  
  return data;
  
} catch (error) {
  // Log error for debugging
  console.error('Fetch error:', error);
  
  // Show user-friendly message
  showErrorMessage('Failed to load data. Please try again.');
  
  return null; // Return fallback value
}


CORS (Cross-Origin Resource Sharing):
--------------------------------------
- Browser security feature
- Prevents requests to different domains
- MockAPI.io has CORS enabled
- For custom APIs, server must allow CORS

                    9. CSS FRAMEWORK COMPARISON
===============================================================================

MATERIALIZE CSS (Stage 1 & 2)
------------------------------
Pros:
  - Component-based
  - Material Design principles
  - Pre-built components (cards, buttons, grids)
  - Less customization needed

Cons:
  - Larger file size
  - Less flexibility
  - Specific design language
  - JavaScript dependencies

Usage:
  <link rel="stylesheet" href="materialize.min.css">
  <div class="card">
    <div class="card-content">Content</div>
  </div>


TAILWIND CSS (Stage 3)
-----------------------
Pros:
  - Utility-first approach
  - Highly customizable
  - Smaller production builds
  - No opinionated design
  - No JavaScript needed
  - Modern workflow

Cons:
  - Steeper learning curve
  - More classes in HTML
  - Requires build process (production)

Usage:
  <div class="bg-blue-500 p-4 rounded-lg shadow-xl">
    <p class="text-white font-bold">Content</p>
  </div>


Common Tailwind Classes:
------------------------
Layout:
  - flex, grid, block, inline-block

  - gap-4, space-y-4

Spacing:
  - p-4 (padding)

Colors:
  - bg-blue-500 (background)

Accessibility:

5. Screen reader friendly


===============================================================================
                    11. COMMON MISTAKES TO AVOID
===============================================================================

1. Forgetting async/await
   ✗ const data = fetch(url); // Returns Promise
   ✓ const data = await fetch(url);

2. Not handling errors
   ✗ const data = await fetch(url);
   ✓ try { const data = await fetch(url); } catch(e) {}

3. Mutating state directly
   ✗ data.items[0] = newValue;
   ✓ Use methods that track changes

4. Not preventing form submission
   ✗ button.addEventListener('click', handler);
   ✓ button.addEventListener('click', (e) => {
       e.preventDefault(); handler();
     });

5. Using innerHTML with user data (XSS risk)
   ✗ element.innerHTML = userInput;
   ✓ element.textContent = userInput;

6. Not checking if element exists
   ✗ element.addEventListener('click', handler);
   ✓ if (element) element.addEventListener('click', handler);

7. Creating multiple event listeners
   ✗ items.forEach(item => 
       item.addEventListener('click', handler));
   ✓ Use event delegation on parent

8. Forgetting to update UI after data changes
   ✗ data.items.push(item); // UI not updated
   ✓ data.items.push(item); updateUI();

9. Not clearing form after submission
   ✗ addItem(); // Form still has values
   ✓ addItem(); clearForm();

10. Mixing concerns (MVC violation)
    ✗ dataController calling UI updates directly
    ✓ appController coordinates between controllers

Snippet 3: Debounce Function
-----------------------------
const debounce = (func, delay) => {
  let timeoutId;
  return (...args) => {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => func(...args), delay);
  };
};

// Usage:
const searchInput = document.querySelector('#search');
searchInput.addEventListener('input', 
  debounce((e) => search(e.target.value), 300)
);

===============================================================================
                    14. PERFORMANCE OPTIMIZATION
===============================================================================

1. Minimize DOM Queries
   Bad:
     for (let i = 0; i < items.length; i++) {
       document.querySelector('#list').appendChild(item);
     }
   
   Good:
     const list = document.querySelector('#list');
     const fragment = document.createDocumentFragment();
     items.forEach(item => fragment.appendChild(item));
     list.appendChild(fragment);


2. Use Event Delegation
   Bad: 100 event listeners on 100 items
   Good: 1 event listener on parent container


3. Debounce Rapid Events
   search.addEventListener('input', debounce(handleSearch, 300));


4. Lazy Load Data
   Load initial data → Load more on scroll/click


5. Cache API Responses
   Store frequently accessed data in memory


6. Optimize Images
   Use appropriate formats and sizes
   Lazy load images


7. Minimize Reflows/Repaints
   Batch DOM changes
   Use CSS classes vs inline styles
