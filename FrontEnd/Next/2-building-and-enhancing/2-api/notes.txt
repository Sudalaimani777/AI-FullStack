CHAPTER 1 :- Building and Managing API routes in Next.js

    Next.js offers built-in backend features that allow developers to create and manage APIs alongside the frontend.

        Supports API routes for handling server-side logic.
        Enables full-stack development within a single project.
        Simplifies backend integration without additional frameworks.

    Setting up API Routes :-
        In Next.js, API routes are defined within the src/app directory. The route structure and naming conventions determine the API endpoint.

    Create a Route File
        Inside your desired directory (e.g., src/app/backend), create a route.js or route.ts file.

        export async function GET()
        {
            return new Response("Response was successful",
                                {status : 200});
        }

    Define HTTP Methods
        The function name must match the HTTP method (e.g., GET, POST, PUT, DELETE).

    Access API Endpoint
        The endpoint is determined by the directory path. For example: http://localhost:3000/backend

    Example: Creating a Basic GET Endpoint :-

        import {NextResponse} from "next/server";

        export async function GET()
        {
            return NextResponse.json(
                {message : "Response was successful"});
        }

    Testing the API
        Use tools like Postman or Thunder Client to send a GET request to

        http://localhost:3000/backend.
           You’ll receive a JSON response:

            { "message": "Response was successful"}

    Best Practices for API Routes :-

        Following best practices for API routes in Next.js helps create secure, maintainable, and scalable backend endpoints.

        1. Organize API Routes
            Place all API-related files under the src/app/api directory.
                src/app/api/get-users/route.js
        
        2. Error Handling
            Use try-catch blocks to handle errors gracefully and provide meaningful error messages.

            try {
                // API logic
            } catch (error) {
                return NextResponse.json(
                    { error: error.message },
                    { status: 500 }
                );
            }
        
        3. Separate Business Logic
            Keep complex logic outside API routes by using utility functions or service files for better code organization and maintainability.

        4. Validation
            Validate incoming request data using libraries like Zod or Joi to ensure data correctness and prevent invalid inputs.

        5. Use Environment Variables
            Avoid hardcoding sensitive information. Store configuration values securely in .env files.

    Advanced API Techniques
        Dynamic Routes: Define dynamic API routes using brackets in the file name.

            src/app/api/users/[id]/route.js

            export async function GET(request, {params})
            {
                const {id} = params;
                return NextResponse.json({userId : id});
            }
            Access the API at: http://localhost:3000/api/users/1

        Database Integration: Replace hardcoded arrays with database queries. Libraries like Prisma or Mongoose work well with Next.js.

    Rate Limiting:
        Protect your APIs from abuse by implementing rate limiting using middleware or packages like express-rate-limit.

CHAPTER 2 :- Rate Limiting 

    Rate limiting controls API traffic to protect servers from abuse and performance issues.

        Limits requests per user within a time window.
        Prevents server overload and high costs.
        Protects against spam and DDoS attacks.
        Example: 5 requests per minute per user.
        Extra requests return HTTP 429 (Too Many Requests).

    Importance of Rate Limiting :-
        Prevent Server Overload: Stops excessive requests from degrading server performance.
        Cost Efficiency: Saves bandwidth and reduces server costs.
        Security: Mitigates risks from malicious attacks like DDoS.
        Fair Usage: Ensures equitable access for all users.

    Popular Rate Limiting Algorithms :-

        Popular rate limiting algorithms define different strategies to control and manage how frequently requests are allowed to access an API.

        Leaky Bucket Algorithm :-
            The Leaky Bucket algorithm smooths request traffic by processing requests at a constant, fixed rate.

            Requests are handled at a steady rate.
            Prevents sudden traffic spikes.
            Extra requests are dropped when capacity is exceeded.
            Suitable for basic and predictable traffic control.

            Working
                Incoming requests are added to a bucket (queue).
                Requests “leak” out at a predefined constant rate.
                When the bucket is full, new incoming requests are rejected.

            Use Case: Simple throttling for evenly spaced request handling.

        Token Bucket Algorithm
            The Token Bucket algorithm allows controlled bursts of requests while enforcing an overall rate limit.

                Uses tokens to represent allowed requests
                Supports short traffic bursts
                Enforces an average request rate
                Commonly used in API rate limiting

            Working
                A bucket starts with a fixed number of tokens.
                Each incoming request consumes one token.
                Tokens are refilled at a fixed rate over time.
                Requests are rejected when no tokens are available.

            Use Case: Burst requests with periodic replenishment.

        Challenges of Rate Limiting Algorithms
            Performance overhead: High traffic increases memory and processing cost.
            Fairness issues: Equal rate limits across users or IPs are hard to ensure.
            Configuration complexity: Selecting and tuning limits is challenging.
            Scalability issues: Multiple instances can cause inconsistent limits without centralized storage (e.g., Redis).

    Centralized Rate Limiting with Redis

            Redis enables centralized rate limiting by maintaining request counts in a fast, shared in-memory store across all server instances.

            Acts as a common store for tracking API requests.
            Ensures consistent limits in distributed systems.
            Handles high request volumes efficiently.
            Integrates well with load-balanced architectures.

        Advantages of Redis:
            Centralized Management: Single source for managing request limits across all server instances.
            High Performance: Fast read/write operations ideal for real-time rate limiting.
            Scalability: Works seamlessly with load-balanced environments.

    Implementing Rate Limiting in Next.js :-

        Rate limiting in Next.js is implemented by tracking and controlling API requests at the server or middleware level to protect endpoints from excessive traffic.

        Setting Up Redis
            You can use a Redis instance via:

            Self-Hosting: Spin up a Redis instance using Docker.
            Managed Solutions: Services like Upstash or AWS ElastiCache.

        Installing Required Packages
            Install the Redis and rate-limiting packages: npm install @upstash/redis @upstash/rate-limit
