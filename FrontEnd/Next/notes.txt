1) Installation :-
    There are two ways to install the next js
        i)  npx create-next-app@latest .  //Install directly in the root folder
        ii) npx create-next-app@latest    //Create a new folder as a root folder and install next js

2) Folder Structure :-

    node modules -> Have all the packages and the source code of the dependencies that we installed
    src -> Holds all the logic and UI files

    gitIgnore -> User to restrict the code that we don't wanna push it into the GitHub

    .next -> Automatically generated by Next.js. It stores compiled files,cache and build output required to run the application.We normally don't edit or push this folder to GitHub.

    app -> Holds the main application UI and routing structure of the Next.js application when using the App Router.

       page.tsx -> Defines the UI/page for a route
       layout.tsx -> Defines shared UI/layout for multiple pages
       loading.tsx -> Displays loading UI
       error.tsx -> Handles errors for a route
       not-found.tsx -> Displays the not-found page
       route.ts -> Used to create API Route Handlers
       globals.css -> Contains global CSS

    public -> Holds all the static files/assets that need to be directly accessible from the browser.

          Example:
              public/logo.png -> /logo.png

          It can contain:
              - Images
              - Icons
              - Fonts
              - PDFs
              - Videos
              - Other static files

    eslint.config.mjs -> Contains the configuration for ESLint. ESLint is used to check the code for potential errors, bad coding patterns and code-quality issues.

                     It helps us:
                         - Find unused variables
                         - Detect common coding mistakes
                         - Maintain code quality
                         - Follow coding rules and standards

    ESLint -> Checks your code
    eslint.config.mjs -> Tells ESLint what rules to follow

    next-env.d.ts -> Automatically generated by Next.js. It provides the TypeScript type information required by Next.js and helps TypeScript understand Next.js-specific types.We normally don't edit this file manually.

    next.config.ts -> Contains the configuration settings for Next.js. It is used to customize how Next.js behaves while developing, building and running the application. Simply Configuration of Next.js

                  It can be used to configure:
                      - Image settings
                      - Redirects
                      - Rewrites
                      - HTTP headers
                      - Other Next.js features and behavior

    package.json -> Contains the project information, dependencies and scripts required to manage and run the application.

                It contains:
                    - Project name and version
                    - Dependencies
                    - Development dependencies
                    - Scripts/commands

                Example:
                    npm run dev    -> Starts the development server
                    npm run build  -> Creates a production build
                    npm start      -> Starts the production server
                    npm run lint   -> Runs ESLint

    package-lock.json -> Stores the exact versions and dependency information installed by npm. It ensures that the same dependency versions are installed across different machines.It is automatically generated/updated by npm.We normally don't edit it manually.

            package.json
                ↓
    Defines required packages
                ↓
        package-lock.json
                ↓
    Locks exact dependency versions
                ↓
            npm install
                ↓
            node_modules/

    postcss.config.mjs -> Contains the configuration for PostCSS. PostCSS is used to process and transform CSS files and apply CSS-related plugins. postcss.config.mjs -> CSS processing configuration

                      It is commonly used with:
                          - Tailwind CSS
                          - Other PostCSS plugins

    tsconfig.json -> Contains the configuration settings for TypeScript. It
                 controls how TypeScript checks and handles the code
                 in the project.

                 It is used to configure:
                     - Type checking
                     - Strictness
                     - Module settings
                     - JSX settings
                     - Path aliases
                     - Which files TypeScript should include/exclude


3)Routing :-

    app 
        /dashboard
            page.jsx
            [user]
                page.jsx
            layout.jsx

        The URL will be :- http://localhost:3000/dashboard/user

    This is known as file based routing
    The layout.jsx is used to handle the custom features for that particular folder like it show all the folder like navbar for the entire UI

4)Route Grouping :-
    It is a technique which helps to organize the routes into a folder without affecting  the URL path.
    Mainly used to keep the app folder clean and for applying different layouts to different sections of the application

    app/
    ├── (auth)/
    │       ├── login/
    │       │   └── page.tsx
    │       └── register/
    │       └── page.tsx
    │
    ├── (dashboard)/
    │       ├── dashboard/
    │       │   └── page.tsx
    │       └── profile/
    │           └── page.tsx
    │
    └── page.tsx

    Here, the (auth) and the (dashboard) is not become the part of our URL  
        http://localhost:3000/login
        http://localhost:3000/dashboard
        http://localhost:3000/profile
