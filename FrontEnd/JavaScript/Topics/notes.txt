CHAPTER 3: VARIABLES
===============================================

┌─────────────────────────────────────────────┐
│  WHAT ARE VARIABLES?                       │
└─────────────────────────────────────────────┘

Variables are containers that store data values. They act as labeled storage locations in memory where you can save, retrieve, and manipulate information throughout your program.

┌─────────────────────────────────────────────┐
│  WHY USE VARIABLES?                        │
└─────────────────────────────────────────────┘

• Store data for later use
• Make code readable and maintainable
• Avoid repeating values throughout code
• Enable dynamic programming
• Facilitate data manipulation
• Create reusable code components

┌─────────────────────────────────────────────┐
│  WHEN TO USE EACH TYPE?                    │
└─────────────────────────────────────────────┘

• var - Legacy code only (avoid in new code)
• let - When value will change (counters, loops, reassignment)
• const - Default choice (constants, objects, arrays, functions)

┌─────────────────────────────────────────────┐
│  ADVANTAGES OF let & const (ES6)           │
└─────────────────────────────────────────────┘

✓ Block scope - prevents variable leaking
✓ No hoisting issues - clearer behavior
✓ Temporal dead zone - catches errors early
✓ Prevents accidental re-declaration
✓ More predictable behavior
✓ Better for functional programming
✓ Encourages immutability (const)

┌─────────────────────────────────────────────┐
│  DISADVANTAGES OF var                       │
└─────────────────────────────────────────────┘

✗ Function/global scope - can cause bugs
✗ Hoisting confusion - can use before declaration
✗ Can be re-declared - leads to errors
✗ No block scope - leaks outside blocks
✗ Harder to debug
✗ Not recommended in modern JavaScript

Three Types of Variable Declarations in JavaScript:

1. var (Old way - avoid using)
   • Scope: Global or Function scope
   • Re-assignable: ✓ YES
   • Re-declarable: ✓ YES
   Example: var name = "John";
   
2. let (Modern - Use for changing values)
   • Scope: Block scope { }
   • Re-assignable: ✓ YES
   • Re-declarable: ✗ NO
   Example: let age = 25;
   
3. const (Modern - Use for constants)
   • Scope: Block scope { }
   • Re-assignable: ✗ NO
   • Re-declarable: ✗ NO
   Example: const PI = 3.14;

Understanding Undefined:
    • Variable is declared: ✓ YES
    • Value is assigned: ✗ NO
    Example:
        let myVar;          // myVar is undefined
        console.log(myVar); // Output: undefined

Variable Naming Conventions:
    
    ✓ CORRECT METHODS:
        • camelCase - let userName;        // ⭐ Most Preferred
        • kebab-case - let user-name;      // Used in CSS
        • PascalCase - let UserName;       // Used for classes
        • Dollar prefix - let $userName;   // Valid in JS
        • Underscore - let _userName;      // Valid in JS
        • Normal - let username;           // Valid but less readable
    
    ✗ INCORRECT METHODS:
        • Starting with number - let 1user;          // ❌ Error
        • Special characters - let user@name;        // ❌ Error (except $ and _)
        • Reserved keywords - let class;             // ❌ Error
        • Spaces - let user name;                    // ❌ Error
    
    Rules:
        → Variable names must start with a letter, $, or _
        → Cannot start with a number
        → Case-sensitive (userName ≠ username)
        → Cannot use reserved keywords (let, const, if, for, etc.)

CHAPTER 4: DATA TYPES
===============================================

┌─────────────────────────────────────────────┐
│  WHAT ARE DATA TYPES?                      │
└─────────────────────────────────────────────┘

Data types define the kind of data that can be stored and manipulated in a program. JavaScript categorizes data into primitive (simple, immutable values) and non-primitive (complex, mutable objects).

┌─────────────────────────────────────────────┐
│  WHY ARE DATA TYPES IMPORTANT?             │
└─────────────────────────────────────────────┘

• Determine how memory is allocated
• Define what operations can be performed on data
• Help prevent errors and bugs
• Enable type checking and validation
• Optimize code performance
• Make code more predictable and maintainable

┌─────────────────────────────────────────────┐
│  WHEN TO USE EACH TYPE?                    │
└─────────────────────────────────────────────┘

Primitive Types:
• String - Text data, names, messages
• Number - Calculations, ages, prices, counters
• Boolean - Conditions, flags, true/false states
• Null - Intentionally empty values
• Undefined - Missing or uninitialized values

Non-Primitive Types:
• Arrays - Lists of items, collections
• Objects - Complex data structures, entities

┌─────────────────────────────────────────────┐
│  ADVANTAGES                                 │
└─────────────────────────────────────────────┘

Primitive Types:
✓ Immutable - cannot be changed, safer
✓ Memory efficient - stored by value
✓ Fast comparison - direct value comparison
✓ Predictable behavior

Non-Primitive Types:
✓ Can store complex data structures
✓ Mutable - can be modified
✓ Store multiple values together
✓ Reference-based - efficient for large data

┌─────────────────────────────────────────────┐
│  DISADVANTAGES                              │
└─────────────────────────────────────────────┘

Primitive Types:
✗ Cannot store complex data
✗ Limited to single values
✗ No methods (except through wrapper objects)

Non-Primitive Types:
✗ Reference issues - copying creates reference, not new object
✗ More memory usage
✗ Comparison complexity - compares references, not values
✗ Mutability can lead to unintended changes

JavaScript has TWO main categories of data types:

┌─────────────────────────────────────────────┐
│  I. PRIMITIVE DATA TYPES (Immutable)       │
└─────────────────────────────────────────────┘

1. String
   • Group of characters enclosed in quotes
   • Syntax: "text", 'text', or `text`
   • Example: 
       let name = "John";
       let greeting = 'Hello';
       let template = `Hi ${name}`;  // Template literal

2. Number
   • Numeric values (integers and decimals)
   • Example: 
       let age = 25;
       let price = 99.99;
       let negative = -10;

3. Boolean
   • Logical data type with only two values
   • Values: true or false
   • Example:
       let isStudent = true;
       let isLoggedIn = false;

4. Null
   • Intentional absence of any value
   • Must be assigned explicitly
   • Example: let data = null;

5. Undefined
   • Variable declared but not assigned a value
   • Automatically assigned by JavaScript
   • Example: 
       let x;
       console.log(x); // undefined

┌─────────────────────────────────────────────┐
│  II. NON-PRIMITIVE (REFERENCE) DATA TYPES  │
└─────────────────────────────────────────────┘

1. ARRAYS
   
   Definition:
       • Collection of multiple values stored in a single variable
       • Can hold different data types: strings, numbers, booleans, etc.
       • Values are accessed by index number (starting from 0)
   
   Syntax:
       const myArray = ["Hello", 2, true, null];
   
   Accessing Array Elements:
       console.log(myArray[0]);  // "Hello" (first element)
       console.log(myArray[1]);  // 2 (second element)
   
   Array Property:
       • .length - Returns the total number of elements
       Example: myArray.length; // 4
   
   Common Array Methods:
       
       Adding Elements:
       • push() - Adds element(s) at the END of the array
         Example: myArray.push("new item");
       
       • unshift() - Adds element(s) at the BEGINNING (index 0)
         Example: myArray.unshift("first item");
       
       Removing Elements:
       • pop() - Removes the LAST element
         Example: myArray.pop();
       
       • shift() - Removes the FIRST element (at index 0)
         Example: myArray.shift();
       
       Other Useful Methods:
       • indexOf() - Find the index of an element
       • includes() - Check if element exists
       • slice() - Extract a portion of array
       • splice() - Add/remove elements at specific position

2. OBJECTS
   
   Definition:
       • Collection of key-value pairs (properties)
       • Similar to arrays but uses named keys instead of numeric indexes
       • Each value must have a corresponding key
   
   Syntax:
       const person = {
           name: "Sudalaimani",
           age: 22,
           isStudent: true,
           hobbies: ["coding", "reading"]
       };
   
   Accessing Object Properties:
       
       Method 1 - Dot Notation (Most Common):
           console.log(person.name);  // Output: "Sudalaimani"
           console.log(person.age);   // Output: 22
       
       Method 2 - Bracket Notation:
           console.log(person["name"]);  // Output: "Sudalaimani"
           console.log(person["age"]);   // Output: 22
   
   Adding/Modifying Properties:
       person.city = "Chennai";      // Add new property
       person.age = 23;              // Modify existing property
   
   Deleting Properties:
       delete person.isStudent;

┌─────────────────────────────────────────────┐
│  CHECKING DATA TYPES                        │
└─────────────────────────────────────────────┘

Use typeof operator to check the data type:
    console.log(typeof "Hello");     // "string"
    console.log(typeof 42);          // "number"
    console.log(typeof true);        // "boolean"
    console.log(typeof undefined);   // "undefined"
    console.log(typeof null);        // "object" (known JS quirk)
    console.log(typeof [1,2,3]);     // "object"
    console.log(typeof {name: "x"}); // "object"

│  WHEN TO USE TYPE CONVERSION?              │
└─────────────────────────────────────────────┘

• Converting user input for calculations
• Parsing API responses
• Formatting data for display
• Performing type-specific operations

• Working with mixed data types

┌─────────────────────────────────────────────┐
│  ADVANTAGES                                 │
└─────────────────────────────────────────────┘

✓ Code clarity - explicit conversion is readable

✓ Predictable results - controlled conversion behavior

┌─────────────────────────────────────────────┐
│  DISADVANTAGES                              │
└─────────────────────────────────────────────┘

✗ Need to handle edge cases (null, undefined)
✗ Implicit conversion can be confusing
✗ Extra code for validation

Type conversion (also called type casting) is the process of converting a value from one data type to another.

┌─────────────────────────────────────────────┐
│  CONVERTING TO STRING                       │
└─────────────────────────────────────────────┘

1. Number to String:
   
   Method: String() constructor
   
   Example:
       let value = String(7);
       console.log(value);        // "7"
       console.log(typeof value); // "string"
       
       value = String(4 + 4);
       console.log(value);        // "8"
       console.log(typeof value); // "string"

2. Boolean to String:
   
   Example:
       let value = String(true);
       console.log(value);        // "true"
       console.log(typeof value); // "string"

3. Array to String:
   
   Example:
       let value = String(["Apple", "Orange"]);
       console.log(value);        // "Apple,Orange"
       console.log(typeof value); // "string"

┌─────────────────────────────────────────────┐
│  CONVERTING TO NUMBER                       │
└─────────────────────────────────────────────┘

1. String to Number:
   
   Method: Number() constructor
   
   Example:
       let value = Number("55");
       console.log(value);        // 55
       console.log(typeof value); // "number"
       
       value = Number("Hello");
       console.log(value);        // NaN (Not a Number)
       
       value = Number("5" + "5");
       console.log(value);        // 55
       
       value = Number("5 + 5");
       console.log(value);        // NaN (string expression)

2. Array to Number:
   
   Example:
       let value = Number([1, 2, 3]);
       console.log(value);        // NaN (cannot convert array to number)

┌─────────────────────────────────────────────┐
│  CONVERTING TO BOOLEAN                      │
└─────────────────────────────────────────────┘

Method: Boolean() constructor

Falsy Values (convert to false):
    • false
    • 0 (zero)
    • "" (empty string)
    • null
    • undefined
    • NaN

Truthy Values (convert to true):
    • Any non-zero number (1, 2, -1, etc.)
    • Any non-empty string
    • Arrays (even empty)
    • Objects (even empty)

Examples:
    let value = Boolean();          // false (no value)
    console.log(value);
    
    value = Boolean("Hello");       // true (non-empty string)
    console.log(value);
    
    value = Boolean(0);             // false (zero)
    console.log(value);
    
    value = Boolean(1);             // true (non-zero)
    console.log(value);
    
    value = Boolean(2);             // true (has value)
    console.log(value);
    
    value = Boolean("Hi");          // true (non-empty string)
    console.log(value);
    
    value = Boolean(null);          // false (null value)
    console.log(value);

┌─────────────────────────────────────────────┐
│  CONVERTING TO ARRAY                        │
└─────────────────────────────────────────────┘

String to Array:
   
   Method: Array() constructor
   
   Example:
       let value = Array("Hello");
       console.log(value);        // ["Hello"]
       console.log(typeof value); // "object"

┌─────────────────────────────────────────────┐
│  PARSING NUMBERS                            │
└─────────────────────────────────────────────┘

1. parseInt() - Convert to Integer:
   
   • Parses a string and returns an integer
   • Removes decimal part
   
   Example:
       let value = parseInt(100.4);
       console.log(value);        // 100
       
       value = parseInt("42");
       console.log(value);        // 42
       
       value = parseInt("42.99");
       console.log(value);        // 42

2. parseFloat() - Convert to Float:
   
   • Parses a string and returns a floating-point number
   • Keeps decimal part
   
   Example:
       let value = parseFloat(10.333);
       console.log(value);        // 10.333
       
       value = parseFloat("3.14");
       console.log(value);        // 3.14

Key Differences:
    parseInt()    → Returns whole numbers (integers)
    parseFloat()  → Returns decimal numbers (floats)
    Number()      → Converts entire value, returns NaN if invalid

Working with numbers and performing mathematical calculations.

┌─────────────────────────────────────────────┐
│  BASIC ARITHMETIC OPERATORS                 │
└─────────────────────────────────────────────┘

JavaScript supports the following arithmetic operators:

Operator    Description              Example     Result
--------    -----------              -------     ------
   +        Addition                 20 + 10     30
   -        Subtraction              20 - 10     10
   *        Multiplication           20 * 10     200
   /        Division                 20 / 10     2
   %        Modulo (Remainder)       20 % 10     0
   **       Exponentiation           2 ** 3      8

Example Code:
    const numOne = 20;
    const numTwo = 10;
    let value;
    
    value = numOne + numTwo;       // 30
    value = numOne - numTwo;       // 10
    value = numOne * numTwo;       // 200
    value = numOne / numTwo;       // 2
    value = numOne % numTwo;       // 0

┌─────────────────────────────────────────────┐
│  MATH OBJECT                                │
└─────────────────────────────────────────────┘

JavaScript's built-in Math object provides mathematical functions and constants.

1. Math.PI
   • Returns the value of PI (π)
   • Value: 3.141592653589793
   
   Example:
       let value = Math.PI;
       console.log(value);  // 3.141592653589793

2. Math.round()
   • Rounds to the nearest integer
   • .5 and above rounds up, below .5 rounds down
   
   Example:
       let value = Math.round(2.5);   // 3
       value = Math.round(2.1);       // 2
       value = Math.round(2.9);       // 3

3. Math.ceil()
   • Rounds UP to the nearest integer
   • Always rounds to the higher value
   
   Example:
       let value = Math.ceil(2.1);    // 3
       value = Math.ceil(2.9);        // 3

4. Math.floor()
   • Rounds DOWN to the nearest integer
   • Always rounds to the lower value
   
   Example:
       let value = Math.floor(2.1);   // 2
       value = Math.floor(2.9);       // 2

5. Math.sqrt()
   • Returns the square root of a number
   
   Example:
       let value = Math.sqrt(100);    // 10
       value = Math.sqrt(64);         // 8

6. Math.abs()
   • Returns the absolute (positive) value
   • Removes negative sign
   
   Example:
       let value = Math.abs(-3);      // 3
       value = Math.abs(-10);         // 10

7. Math.min()
   • Returns the smallest number from arguments
   
   Example:
       let value = Math.min(1, 2, 3);        // 1
       value = Math.min(10, 5, 20, 3);       // 3

8. Math.max()
   • Returns the largest number from arguments
   
   Example:
       let value = Math.max(1, 3, 45);       // 45
       value = Math.max(10, 5, 20, 3);       // 20

9. Math.random()
   • Returns a random decimal number between 0 (inclusive) and 1 (exclusive)
   • Useful for generating random numbers
   
   Example:
       let value = Math.random();
       console.log(value);  // e.g., 0.12345...
       
       // To get a random number within a range (e.g., 1 to 10)
       value = Math.floor(Math.random() * 10 + 1);
       console.log(value);  // Random integer between 1 and 10

===============================================

┌─────────────────────────────────────────────┐
│  WHAT ARE STRINGS?                         │
└─────────────────────────────────────────────┘

Strings are sequences of characters used to represent text. They are immutable (cannot be changed after creation) and are enclosed in quotes (single, double, or backticks).

┌─────────────────────────────────────────────┐
│  WHY USE STRING METHODS?                   │
└─────────────────────────────────────────────┘

• Text manipulation and formatting
• User input validation
• Search and replace operations
• Data parsing and processing
• Creating dynamic messages
• URL and path manipulation
• String comparison and matching

┌─────────────────────────────────────────────┐
│  WHEN TO USE STRING METHODS?               │
└─────────────────────────────────────────────┘

• Form validation (email, password, etc.)
• Text formatting (capitalization, trimming)
• Searching text content
• Extracting substrings
• Building dynamic content
• Data cleaning and sanitization
• Creating SEO-friendly URLs
• Parsing CSV or text files

┌─────────────────────────────────────────────┐
│  ADVANTAGES                                 │
└─────────────────────────────────────────────┘

✓ Rich built-in methods - extensive functionality
✓ Immutable - safe from accidental changes
✓ Easy to use - intuitive method names
✓ Chainable methods - combine operations
✓ Unicode support - international characters
✓ Template literals - modern string formatting
✓ Regular expression support

┌─────────────────────────────────────────────┐
│  DISADVANTAGES                              │
└─────────────────────────────────────────────┘

✗ Immutable - creates new string for each operation (memory)
✗ Performance - string concatenation in loops is slow
✗ No built-in trim() for older browsers
✗ Case-sensitive comparisons require extra care

1. length

   • Method to join strings (alternative to +)

┌─────────────────────────────────────────────┐
│  SYNTAX                                     │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│  FEATURES & ADVANTAGES                      │
└─────────────────────────────────────────────┘

1. Expression Interpolation
   • Easily embed variables and expressions directly into a string
   • Syntax: ${expression}
   
   Old Way (Concatenation):
       const name = "John";
       const age = 30;
       const message = "My name is " + name + " and I am " + age + " years old.";
   
   New Way (Template Literal):
       const name = "John";
       const age = 30;
       const message = `My name is ${name} and I am ${age} years old.`;

2. Multi-line Strings
   • Create strings that span multiple lines without using `\n`
   
   Old Way:
       const html = '<ul>\n' +
                    '  <li>Item 1</li>\n' +
                    '  <li>Item 2</li>\n' +
                    '</ul>';
   
   New Way:
       const html = `
           <ul>
             <li>Item 1</li>
             <li>Item 2</li>
           </ul>
       `;

3. Tagged Templates (Advanced)
   • Allows you to parse template literals with a function.
   
   Example:
       function myTag(strings, personExp, ageExp) {
           const str0 = strings[0]; // "That "
           const str1 = strings[1]; // " is a "
           const str2 = strings[2]; // "."
           
           const ageStr = ageExp > 99 ? 'centenarian' : 'youngster';
           
           return `${str0}${personExp}${str1}${ageStr}${str2}`;
       }
       
       const person = 'Mike';
       const age = 28;
       const output = myTag`That ${person} is a ${age}.`;
       console.log(output); // "That Mike is a youngster."

1. push()
   • Adds one or more elements to the END of an array
   • Returns the new length of the array

3. unshift()

   • Returns the new length of the array

   • Returns the removed element

5. indexOf()

   • Returns -1 if the element is not present

7. slice()
   • Returns a shallow copy of a portion of an array into a new array
   • Does NOT modify the original array

       console.log(subArray); // [2, 3, 4]

8. splice()
   • Changes the contents of an array by removing or replacing existing elements and/or adding new elements
   • MODIFIES the original array
   
   Syntax: splice(start, deleteCount, item1, item2, ...)
   
   Example (Removing):
       const numbers = [1, 2, 3, 4, 5];
       numbers.splice(2, 2); // remove 2 elements starting from index 2
       console.log(numbers); // [1, 2, 5]
   
   Example (Adding):
       const numbers = [1, 2, 5];
       numbers.splice(2, 0, 3, 4); // at index 2, delete 0, add 3 and 4

Objects are collections of key-value pairs. They are a fundamental building block in JavaScript.

┌─────────────────────────────────────────────┐
│  OBJECT LITERALS                            │
└─────────────────────────────────────────────┘

The most common way to create an object.

Syntax:
    const person = {
        name: "Sudalaimani",
        age: 22,
        isStudent: true,
        address: {
            city: "Ettaiyapuram",
            street: "East Street"
        },
        hobbies: ["Playing", "Studying"],
        // A function inside an object is called a method
        getFullName: function() {
            return this.name;
        }
    };

Key Characteristics:
    • Reference Type: Objects are not stored directly in variables; the variable holds a reference (or pointer) to the object's location in memory.
    • Mutable: You can change, add, or remove properties after the object is created.

┌─────────────────────────────────────────────┐
│  ACCESSING PROPERTIES                       │
└─────────────────────────────────────────────┘

1. Dot Notation (.)

   • The easiest and most common way.
   • Cannot be used if the key is a number or contains special characters/spaces.
   
   Example:
       console.log(person.name);      // "Sudalaimani"
       console.log(person.address.city); // "Ettaiyapuram"

2. Bracket Notation ([])
   • More versatile.
   • Use when the key is stored in a variable or contains spaces/special characters.
   
   Example:
       console.log(person["age"]);         // 22
       let key = "name";
       console.log(person[key]);           // "Sudalaimani"
       // person."City" would be an error, but person["City"] works.

┌─────────────────────────────────────────────┐
│  MANIPULATING OBJECTS                       │
└─────────────────────────────────────────────┘

1. Adding/Updating Properties:
   person.email = "test@example.com"; // Adds a new property
   person.age = 23;                     // Updates an existing property

2. Calling Methods:
   console.log(person.getFullName());   // "Sudalaimani"

┌─────────────────────────────────────────────┐
│  CONSTRUCTOR FUNCTIONS (ES5)                │
└─────────────────────────────────────────────┘

Constructor functions are blueprints for creating multiple objects with the same structure.

Constructor Rules:
    1. The first letter should be CAPITAL (naming convention)
    2. Use the `new` keyword to create instances
    3. The constructor creates instances of objects

Syntax:
    function UserName(fName, lName, address) {
        this.fName = fName;
        this.lName = lName;
        this.address = address;
        this.getFullName = function() {
            return this.fName + " " + this.lName;
        }
    }

Creating Instances:
    const personOne = new UserName("Sudalai", "mani", "Ettaiyapuram");
    const personTwo = new UserName("Arun", "Kumar", "Chennai");
    
    console.log(personOne.getFullName()); // "Sudalai mani"
    console.log(personTwo.getFullName()); // "Arun Kumar"

┌─────────────────────────────────────────────┐
│  THE 'this' KEYWORD                         │
└─────────────────────────────────────────────┘

The `this` keyword behaves differently depending on the context:

1. Global Scope:
   • `this` points to the window object
   
   Example:
       console.log(this); // window object
       // this === window

2. Normal Function:
   • `this` points to the window object
   
   Example:
       function normal() {
           console.log(this); // window object
       }
       normal();

3. Object Method:
   • `this` refers to the parent object (the object itself)
   
   Example:
       const obj = {
           name: "Sudalaimani",
           getName: function() {
               return this.name; // 'this' refers to obj
           }
       };
       console.log(obj.getName()); // "Sudalaimani"

4. Nested Function inside Object Method:
   • `this` returns the window object (because it's a standalone function)
   
   Example:
       const nestedMethod = {
           key: function() {
               console.log(this); // Returns nestedMethod object
               
               function separateFunction() {
                   console.log(this); // Returns window object
               }
               separateFunction();
           }
       };

5. Arrow Function (Lexical this):
   • Arrow functions inherit `this` from their parent scope
   • Use arrow functions to fix the nested function issue
   
   Example:
       const fixedMethod = {
           lexical: function() {
               console.log(this); // Returns the object
               
               const lexicalThis = () => {
                   console.log(this); // Also returns the object
               };
               lexicalThis();
           }
       };

┌─────────────────────────────────────────────┐
│  BUILT-IN CONSTRUCTORS                      │
└─────────────────────────────────────────────┘

JavaScript provides built-in constructor functions for primitive types:

1. String Constructor:
   const str1 = "Hello";              // String literal (primitive)
   const str2 = new String("Hello");  // String object
   
   typeof str1; // "string"
   typeof str2; // "object"

2. Number Constructor:
   const num1 = 42;                   // Number literal (primitive)
   const num2 = new Number(42);       // Number object
   
   typeof num1; // "number"
   typeof num2; // "object"

3. Array Constructor:
   const arr1 = [1, 2, 3];            // Array literal
   const arr2 = new Array(1, 2, 3);   // Array constructor
   
   // Both are functionally the same

4. Object Constructor:
   const obj1 = { name: "Mani" };     // Object literal
   const obj2 = new Object();         // Object constructor
   obj2.name = "Mani";

Key Difference:
    • Literals create primitive types (for String, Number)
    • Constructors create object wrappers
    • Use literals for better performance and simplicity

┌─────────────────────────────────────────────┐
│  PROTOTYPES                                 │
└─────────────────────────────────────────────┘

What is a Prototype?
    • Every JavaScript object has a prototype
    • A prototype is an object from which other objects inherit properties and methods
    • Prototypes enable efficient memory usage by sharing methods

Prototype Chain:
    • When you access a property/method on an object, JavaScript looks for it in:
      1. The object itself
      2. The object's prototype
      3. The prototype's prototype (and so on)
    • This chain continues until it reaches the base prototype (null)

Two Types of Prototypes:
    1. Normal Prototype - Used for inheritance
    2. Base Prototype - The root of the prototype chain (don't modify this)

┌─────────────────────────────────────────────┐
│  ADDING METHODS TO PROTOTYPE                │
└─────────────────────────────────────────────┘

Instead of adding methods inside the constructor (which creates a new copy for each instance), add them to the prototype:

Without Prototype (Inefficient):
    function User(fName, lName) {
        this.firstName = fName;
        this.lastName = lName;
        this.getFullName = function() {  // New copy for each instance
            return this.firstName + this.lastName;
        }
    }

With Prototype (Efficient):
    function User(fName, lName) {
        this.firstName = fName;
        this.lastName = lName;
    }
    
    // Add method to prototype (shared by all instances)
    User.prototype.getFullName = function() {
        return this.firstName + this.lastName;
    };
    
    const user1 = new User("Sudalai", "mani");
    console.log(user1.getFullName()); // Method is in prototype, not object
    console.log(User.prototype);      // Shows the getFullName method

Benefits:
    ✓ Memory efficient - method is shared, not duplicated
    ✓ All instances reference the same method
    ✓ Can add methods after instances are created

┌─────────────────────────────────────────────┐
│  PROTOTYPE INHERITANCE                      │
└─────────────────────────────────────────────┘

Prototype inheritance allows one constructor to inherit properties and methods from another.

Example:
    // Parent Constructor
    function UserData(fName, lName) {
        this.firstName = fName;
        this.lastName = lName;
    }
    
    // Add methods to parent prototype
    UserData.prototype.greeting = function() {
        return `Hello ${this.firstName + this.lastName}`;
    };
    
    UserData.prototype.getFullName = function() {
        return this.firstName + this.lastName;
    };

    // Child Constructor
    function Customer(fName, lName, email) {
        // Call parent constructor with 'this' context
        UserData.call(this, fName, lName);
        this.email = email;
    }
    
    // Inherit parent's prototype methods
    Customer.prototype = Object.create(UserData.prototype);
    
    const customer1 = new Customer("Kumar", "Sankara", "kumar@gmail.com");
    console.log(customer1.greeting());    // Inherited method works!
    console.log(customer1.getFullName()); // Inherited method works!

Key Methods:
    • call(this, arg1, arg2) - Calls parent constructor with arguments
    • Object.create(prototype) - Creates new object with specified prototype

How it works:
    1. UserData.call(this, fName, lName) - Inherit properties
    2. Customer.prototype = Object.create(UserData.prototype) - Inherit methods
    3. Customer instances now have access to UserData methods

┌─────────────────────────────────────────────┐
│  ES6 CLASSES                                │
└─────────────────────────────────────────────┘

ES6 introduced the `class` keyword - a cleaner syntax for creating constructor functions and inheritance.

Class Syntax:
    class UserData {
        // Constructor for properties
        constructor(firstName, lastName) {
            this.firstName = firstName;
            this.lastName = lastName;
        }
        
        // Methods (automatically added to prototype)
        getFullName() {
            return `${this.firstName + this.lastName}`;
        }
        
        greet() {
            return `Welcome ${this.firstName + this.lastName}`;
        }
    }
    
    const person1 = new UserData("Sudalai", "mani");
    console.log(person1.getFullName()); // "Sudalaimani"
    console.log(person1.greet());       // "Welcome Sudalaimani"

Key Points:
    • Methods defined in class body are added to prototype
    • Use `constructor()` for properties
    • Don't use `function` keyword for methods inside class

┌─────────────────────────────────────────────┐
│  CLASS INHERITANCE (extends & super)        │
└─────────────────────────────────────────────┘

ES6 provides `extends` and `super` keywords for inheritance:

Syntax:
    class Customer extends UserData {
        constructor(firstName, lastName, email) {
            // Call parent constructor
            super(firstName, lastName);
            this.email = email;
        }
    }
    
    const customer1 = new Customer("Prakash", "raj", "prakash@gmail.com");
    console.log(customer1);
    console.log(customer1.greet());        // Inherited from UserData
    console.log(customer1.getFullName());  // Inherited from UserData

How it works:
    • extends - Inherits all methods from parent class
    • super() - Calls the parent class constructor
    • Must call super() before using 'this' in child constructor

Comparison: ES5 vs ES6
    ES5 (Prototype Inheritance):
        • UserData.call(this, fName, lName)
        • Customer.prototype = Object.create(UserData.prototype)
    
    ES6 (Class Inheritance):
        • extends UserData
        • super(firstName, lastName)

Benefits of ES6 Classes:
    ✓ Cleaner, more readable syntax
    ✓ Easier to understand for developers from other languages
    ✓ Less boilerplate code
    ✓ Still uses prototypes under the hood (syntactic sugar)

Conditional statements control behavior in JavaScript and determine whether or not pieces of code can run.

┌─────────────────────────────────────────────┐
│  IF...ELSE STATEMENT                        │
└─────────────────────────────────────────────┘

Executes a block of code if a specified condition is true. If the condition is false, another block of code can be executed.

Syntax:
    if (condition) {
        // block of code to be executed if the condition is true
    } else {
        // block of code to be executed if the condition is false
    }

Example:
    let age = 18;
    if (age >= 18) {
        console.log("You are an adult.");
    } else {
        console.log("You are a minor.");
    }

┌─────────────────────────────────────────────┐
│  ELSE IF STATEMENT                          │
└─────────────────────────────────────────────┘

Used to specify a new condition to test, if the first condition is false.

Example:
    const color = "red";
    if (color === "blue") {
        console.log("The color is blue");
    } else if (color === "green") {
        console.log("The color is green");
    } else if (color === "red") {
        console.log("The color is red");
    } else {
        console.log("The color is not blue, green, or red");
    }

└─────────────────────────────────────────────┘

Comparison Operators:
    ==      Equal to (value)
    ===     Strictly equal to (value and type)
    !=      Not equal to (value)
    !==     Strictly not equal to (value and type)
    >       Greater than
    <       Less than
    >=      Greater than or equal to
    <=      Less than or equal to

Logical Operators:
    &&      AND (both conditions must be true)
    ||      OR (at least one condition must be true)
    !       NOT (inverts the boolean value)

Example (Logical AND):
    const a = 10;
    const b = 10;
    if (a > 5 && b === 10) {
        console.log("Both conditions are true.");
    }

Example (Logical OR):
    const c = 20;

        console.log("At least one condition is true.");

┌─────────────────────────────────────────────┐
│  DISADVANTAGES                              │
└─────────────────────────────────────────────┘

✗ Only works with exact value matches
✗ Can't use comparison operators (<, >, <=, >=)
✗ Forgetting 'break' causes unintended fall-through
✗ More verbose for simple true/false checks
✗ Not suitable for complex boolean logic
✗ Can't evaluate expressions in case values
✗ Block scoping issues (use {} for each case if needed)

The switch statement is used to perform different actions based on different conditions. It's often a more elegant alternative to a long `if...else if...else` chain.

┌─────────────────────────────────────────────┐
│  SYNTAX                                     │
└─────────────────────────────────────────────┘

    switch(expression) {
        case value1:
            // code block
            break;
        case value2:
            // code block
            break;
        default:
            // code block if no case matches
    }

How it works:
    1. The `expression` is evaluated once.
    2. The value of the expression is compared with the values of each `case`.
    3. If there is a match, the associated block of code is executed.
    4. The `break` keyword stops the execution inside the switch block. Without it, execution would "fall through" to the next case.
    5. The `default` block is executed if no case matches.

Example:
    const color = "red";
    switch(color) {
        case "blue":
            console.log("The color is blue");
            break;
        case "red":
            console.log("The color is red");
            break;
        default:
            console.log("Not a valid color");
    }

Using with Expressions:
    const age = 20;
    switch(true) {
        case age >= 18:
            console.log("Wow, you are an adult");
            break;
        case age < 18:
            console.log("Sorry, you are not an adult");
            break;
        default:
            console.log("Not a valid age");
    }

┌─────────────────────────────────────────────┐

└─────────────────────────────────────────────┘

A function defined with the `function` keyword. These are "hoisted," meaning they can be called before they are defined in the code.

Syntax:
    function functionName(parameter1, parameter2) {
        // code to be executed
        return parameter1 + parameter2;
    }

Example:
    // Calling the function
    let result = greet("Mani");
    console.log(result); // "Hello Mani"

    // Defining the function

        return `Hello ${user}`;
    }

┌─────────────────────────────────────────────┐
│  FUNCTION EXPRESSION                        │
└─────────────────────────────────────────────┘

A function created and assigned to a variable. These are not hoisted and cannot be called before they are defined.

Syntax (Anonymous Function):
    const variableName = function(parameter1, parameter2) {
        // code to be executed
    };

Syntax (Arrow Function - ES6):
    const sum = (a, b) => a + b;

Example:
    // console.log(sum(2, 3)); // Throws an error because it's called before definition
    const sum = (a, b) => a + b;

┌─────────────────────────────────────────────┐
│  PARAMETERS & ARGUMENTS                     │

Default Parameters (ES6):
You can provide default values for parameters.

Example:

        return a + b;
    }

┌─────────────────────────────────────────────┐
│  1. ES6 MODULES (IMPORT/EXPORT)            │
└─────────────────────────────────────────────┘

ES6 introduced native module support in JavaScript using `import` and `export` keywords.

A. NAMED EXPORTS
   Export multiple items from a file. Must import with exact same name.

   Syntax:
       // Export while declaring
       export const name = "John";
       export function greet() { return "Hello"; }
       export class User { }

       // Export after declaring
       const age = 25;
       function calculate() { }
       export { age, calculate };

       // Export with rename
       const secret = "123";
       export { secret as password };

B. DEFAULT EXPORT
   Export ONE main thing from a file. Can import with any name.

   Syntax:
       // Export function
       export default function() { 
           console.log("Main function"); 
       }

       // Export class
       export default class User {
           constructor(name) {
               this.name = name;
           }
       }

       // Export value
       const config = { theme: "dark" };
       export default config;

   IMPORTANT: Only ONE default export per file!

C. IMPORTING MODULES

   Import Named Exports:
       // Import specific items
       import { name, greet } from './module.js';

       // Import with rename
       import { password as secret } from './module.js';

       // Import everything as object
       import * as myModule from './module.js';

   Import Default Export:
       // Can use any name
       import myFunction from './module.js';
       import MyClass from './module.js';

   Mixed Import:
       // Both default and named
       import multiply, { PI, add } from './math.js';

D. PRACTICAL EXAMPLE

   File: calculation.js
       export const add = (a, b) => a + b;
       export const subtract = (a, b) => a - b;
       export default function multiply(a, b) {
           return a * b;
       }

   File: main.js
       import multiply, { add, subtract } from './calculation.js';
       
       console.log(add(5, 3));       // 8
       console.log(subtract(10, 4)); // 6
       console.log(multiply(2, 5));  // 10

E. HTML USAGE
   Must use type="module" in script tag:
       <script type="module" src="main.js"></script>

┌─────────────────────────────────────────────┐
│  2. IIFE (IMMEDIATELY INVOKED FUNCTION)    │
└─────────────────────────────────────────────┘

IIFE (Immediately Invoked Function Expression) is a function that runs as soon as it's defined. Used for encapsulation and avoiding global scope pollution.

A. BASIC SYNTAX

   Traditional Function:
       (function() {
           // Code here runs immediately
           console.log("I run right away!");
       })();

   Arrow Function (ES6):
       (() => {
           console.log("Modern IIFE!");
       })();

B. BREAKING DOWN THE SYNTAX

   Step 1: (function() { ... })   ← Wrap in parentheses (makes it an expression)
   Step 2: ()                     ← Call it immediately

   Two Valid Styles:
       // Style 1: Parentheses wrap everything (more common)
       (function() {
           console.log("Style 1");
       })();

       // Style 2: Parentheses wrap only function
       (function() {
           console.log("Style 2");
       }());

C. WHY USE IIFE?

   1. Create Private Variables:
       (function() {
           const secret = "hidden";  // Not accessible outside
           console.log(secret);      // Works here
       })();
       // console.log(secret);       // Error: secret is not defined

   2. Avoid Global Scope Pollution:
       (function() {
           const tempVar = "temporary";
           // Use tempVar here without affecting global scope
       })();

   3. Module Pattern:
       const myModule = (function() {
           // Private variables
           const privateVar = "secret";
           
           // Private function
           function privateFunction() {
               return "private";
           }
           
           // Public API
           return {
               publicMethod: function() {
                   return privateFunction() + " " + privateVar;
               }
           };
       })();
       
       console.log(myModule.publicMethod()); // "private secret"
       // console.log(privateVar);            // Error: not accessible

D. IIFE WITH PARAMETERS

   Pass arguments to IIFE:
       (function(name, age) {
           console.log(`${name} is ${age} years old`);
       })("John", 25);  // "John is 25 years old"

   Using Global Objects:
       (function(window, document) {
           // Now window and document are local parameters
           // Faster access and safe to use
           console.log(window.innerWidth);
       })(window, document);

E. PRACTICAL EXAMPLE - COUNTER

   const counter = (function() {
       let count = 0;  // Private variable
       
       return {
           increment: function() {
               count++;
               return count;
           },
           decrement: function() {
               count--;
               return count;
           },
           getValue: function() {
               return count;
           }
       };
   })();

   console.log(counter.increment()); // 1
   console.log(counter.increment()); // 2
   console.log(counter.getValue());  // 2
   console.log(counter.decrement()); // 1
   // console.log(count);            // Error: count is private

F. MODERN ALTERNATIVES

   In modern JavaScript, ES6 modules often replace IIFE:
   
   Instead of IIFE:
       (function() {
           const private = "data";
           // code
       })();
   
   Use modules:
       // Private by default
       const private = "data";
       
       // Only export what's needed
       export function publicFunction() { }

   Block scoping with let/const:
       {
           const private = "data";  // Block-scoped
           // code
       }
       // private not accessible here

┌─────────────────────────────────────────────┐
│  BEST PRACTICES                             │
└─────────────────────────────────────────────┘

ES6 Modules:
    1. ✓ One module per file for clarity
    2. ✓ Use named exports for multiple utilities
    3. ✓ Use default export for main component/class
    4. ✓ Keep imports at the top of files
    5. ✓ Use absolute paths or module aliases
    6. ✓ Avoid circular dependencies

IIFE:
    1. ✓ Use for immediate execution and encapsulation
    2. ✓ Create module pattern for public/private API
    3. ✓ Pass global objects as parameters
    4. ✓ Use arrow functions for modern code
    5. ✓ Consider ES6 modules for new projects

✓ Persistent - survives page reloads (localStorage)
✓ Larger storage - ~5-10MB (vs 4KB cookies)
✓ No automatic server transmission (unlike cookies)
✓ Synchronous - immediate access
✓ Per-origin storage - isolated by domain
✓ No expiration date (localStorage)

┌─────────────────────────────────────────────┐
│  DISADVANTAGES                              │
└─────────────────────────────────────────────┘

✗ String-only storage - must convert objects
✗ Security risk - accessible via JavaScript
✗ No encryption - data stored in plain text
✗ Size limit - typically 5-10MB
✗ Synchronous - can block main thread
✗ Same-origin policy - not cross-domain
✗ No server-side access
✗ Can be cleared by user

There are TWO types of Web Storage:

┌─────────────────────────────────────────────┐
│  1. LOCALSTORAGE (PERMANENT STORAGE)       │
└─────────────────────────────────────────────┘

localStorage saves data permanently (stays even after closing browser).

A. BASIC OPERATIONS

   Save Data:
       localStorage.setItem('username', 'John');
       localStorage.setItem('age', '25');
       localStorage.setItem('theme', 'dark');

   Get Data:
       const username = localStorage.getItem('username');
       console.log(username); // "John"
       
       const age = localStorage.getItem('age');
       console.log(age); // "25"

   Remove Specific Item:
       localStorage.removeItem('username');

   Clear All Data:
       localStorage.clear();

   Check Item Existence:
       if (localStorage.getItem('theme')) {
           console.log('Theme exists');
       }

B. STORING OBJECTS (JSON)

   Since localStorage only stores strings, use JSON methods:

   Save Object:
       const user = {
           name: 'John Doe',
           age: 30,
           email: 'john@example.com'
       };
       localStorage.setItem('user', JSON.stringify(user));

   Retrieve Object:
       const storedUser = localStorage.getItem('user');
       const userObject = JSON.parse(storedUser);
       console.log(userObject.name); // "John Doe"

   Save Array:
       const fruits = ['Apple', 'Banana', 'Orange'];
       localStorage.setItem('fruits', JSON.stringify(fruits));

   Retrieve Array:
       const storedFruits = localStorage.getItem('fruits');
       const fruitsArray = JSON.parse(storedFruits);
       console.log(fruitsArray[0]); // "Apple"

C. PRACTICAL EXAMPLE - THEME TOGGLE

   // Save theme preference
   function setTheme(theme) {
       localStorage.setItem('theme', theme);
       document.body.className = theme;
   }

   // Load theme on page load
   window.addEventListener('DOMContentLoaded', () => {
       const savedTheme = localStorage.getItem('theme') || 'light';
       document.body.className = savedTheme;
   });

   // Toggle button
   document.getElementById('themeToggle').addEventListener('click', () => {
       const currentTheme = localStorage.getItem('theme') || 'light';
       const newTheme = currentTheme === 'light' ? 'dark' : 'light';
       setTheme(newTheme);
   });

┌─────────────────────────────────────────────┐
│  2. SESSIONSTORAGE (TEMPORARY STORAGE)     │
└─────────────────────────────────────────────┘

sessionStorage saves data temporarily (deleted when tab/window is closed).

A. BASIC OPERATIONS

   Same API as localStorage:

   Save Data:
       sessionStorage.setItem('formData', 'temporary');

   Get Data:
       const data = sessionStorage.getItem('formData');

   Remove Data:
       sessionStorage.removeItem('formData');

   Clear All:
       sessionStorage.clear();

B. PRACTICAL EXAMPLE - FORM AUTO-SAVE

   // Save form data as user types
   document.getElementById('nameInput').addEventListener('input', (e) => {
       sessionStorage.setItem('tempName', e.target.value);
   });

   // Restore form data on page load
   window.addEventListener('DOMContentLoaded', () => {
       const savedName = sessionStorage.getItem('tempName');
       if (savedName) {
           document.getElementById('nameInput').value = savedName;
       }
   });

   // Clear on form submit
   document.getElementById('myForm').addEventListener('submit', () => {
       sessionStorage.removeItem('tempName');
   });

┌─────────────────────────────────────────────┐
│  3. JSON METHODS (for storage)             │
└─────────────────────────────────────────────┘

A. JSON.stringify()
   Converts JavaScript objects/arrays to JSON string for storage.

   Syntax:
       JSON.stringify(value, replacer, space)

   Examples:
       // Simple object
       const obj = { name: "John", age: 30 };
       const jsonString = JSON.stringify(obj);
       console.log(jsonString); // '{"name":"John","age":30}'

       // Array
       const arr = [1, 2, 3];
       const arrString = JSON.stringify(arr);
       console.log(arrString); // '[1,2,3]'

       // Formatted (with spacing)
       const formatted = JSON.stringify(obj, null, 2);
       console.log(formatted);
       // {
       //   "name": "John",
       //   "age": 30
       // }

B. JSON.parse()
   Converts JSON string back to JavaScript object/array.

   Syntax:
       JSON.parse(string)

   Examples:
       // Parse object
       const jsonStr = '{"name":"John","age":30}';
       const obj = JSON.parse(jsonStr);
       console.log(obj.name); // "John"

       // Parse array
       const arrStr = '[1,2,3]';
       const arr = JSON.parse(arrStr);
       console.log(arr[0]); // 1

   Error Handling:
       try {
           const data = JSON.parse(invalidJSON);
       } catch (error) {
           console.error('Invalid JSON:', error);
       }

┌─────────────────────────────────────────────┐
│  LOCALSTORAGE VS SESSIONSTORAGE            │
└─────────────────────────────────────────────┘

Feature              | localStorage      | sessionStorage
---------------------|-------------------|-------------------
Duration             | Permanent         | Until tab close
Scope                | All tabs/windows  | Single tab/window
Survives closing     | YES               | NO
Use case             | Preferences       | Temporary data
Expiration           | Never (manual)    | Tab close
Storage limit        | ~5-10MB           | ~5-10MB
API                  | Same as sessionStorage | Same as localStorage

┌─────────────────────────────────────────────┐
│  PRACTICAL EXAMPLE - SHOPPING CART         │
└─────────────────────────────────────────────┘

// Shopping Cart using localStorage
const cart = {
    // Add item
    addItem: function(product) {
        let items = this.getItems();
        items.push(product);
        localStorage.setItem('cart', JSON.stringify(items));
    },
    
    // Get all items
    getItems: function() {
        const items = localStorage.getItem('cart');
        return items ? JSON.parse(items) : [];
    },
    
    // Remove item
    removeItem: function(index) {
        let items = this.getItems();
        items.splice(index, 1);
        localStorage.setItem('cart', JSON.stringify(items));
    },
    
    // Clear cart
    clear: function() {
        localStorage.removeItem('cart');
    },
    
    // Get total items
    getCount: function() {
        return this.getItems().length;
    }
};

// Usage
cart.addItem({ id: 1, name: 'Laptop', price: 999 });
cart.addItem({ id: 2, name: 'Mouse', price: 25 });
console.log(cart.getItems());    // Array of items
console.log(cart.getCount());    // 2
cart.removeItem(0);              // Remove first item
cart.clear();                     // Empty cart

Security:
    1. ✗ Never store sensitive data (passwords, credit cards)
    2. ✗ Don't store unencrypted authentication tokens
    3. ✓ Validate and sanitize data before storing
    4. ✓ Be aware data is readable by anyone with access

Performance:
    1. ✓ Check storage availability before use
    2. ✓ Use try-catch for JSON operations
    3. ✓ Don't store huge amounts of data
    4. ✓ Clear unused data periodically

Code Quality:
    1. ✓ Create wrapper functions for storage operations
    2. ✓ Handle null/undefined values
    3. ✓ Provide fallback for browsers without support
    4. ✓ Use meaningful key names

Storage Availability Check:
    function storageAvailable(type) {
        try {
            const storage = window[type];
            const test = '__storage_test__';
            storage.setItem(test, test);
            storage.removeItem(test);
            return true;
        } catch(e) {
            return false;
        }
    }

    if (storageAvailable('localStorage')) {
        // Use localStorage
    } else {
        // Use alternative storage or warn user
    }
