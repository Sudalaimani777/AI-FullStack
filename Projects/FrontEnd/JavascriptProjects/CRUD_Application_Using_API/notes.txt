===============================================================================
                    CRUD APPLICATION USING API - DOCUMENTATION
===============================================================================

PROJECT OVERVIEW:
-----------------
A full-featured task management application that implements all CRUD operations
(Create, Read, Update, Delete) using REST API integration with MockAPI. The app
features a modern, responsive UI built with Tailwind CSS and uses ES6 modules
for clean code organization.

PROJECT STRUCTURE:
------------------
1. index.html    - Main HTML structure with Tailwind CDN for styling
2. script.js     - Main application logic and event handlers
3. library.js    - Custom Task class with static methods for API operations
4. notes.txt     - This documentation file

API ENDPOINT:
-------------
Base URL: https://6955ebb8b9b81bad7af1c22f.mockapi.io/api/v1/task
Provider: MockAPI (Free REST API for testing and prototyping)

===============================================================================
                        APPLICATION FEATURES
===============================================================================

1. CREATE (POST):
   - Add new tasks through input form
   - Validates empty input before submission
   - Immediately displays newly created task
   - Resets input field after successful creation

2. READ (GET):
   - Fetches all tasks on page load (DOMContentLoaded event)
   - Displays tasks in a styled card layout
   - Each task shows task text with Edit and Delete buttons

3. UPDATE (PUT):
   - Edit button converts task text to input field
   - Button changes from "Edit" to "Save"
   - Validates non-empty input before updating
   - Updates API and UI upon successful save
   - Reverts to display mode after saving

4. DELETE (DELETE):
   - Delete button with confirmation dialog
   - Removes task from API and DOM
   - Provides error feedback if deletion fails

===============================================================================
                    TECHNICAL IMPLEMENTATION DETAILS
===============================================================================

ARCHITECTURE PATTERN:
---------------------
- Event Delegation: Used for handling Edit/Save/Delete actions
- Separation of Concerns: API logic separated into library.js
- Async/Await: All API calls use modern async/await syntax
- ES6 Modules: Import/Export for code modularity

KEY FUNCTIONS:
--------------
1. loadAllEvents()
   - Registers all event listeners on initialization
   - DOMContentLoaded, form submit, and click events

2. handleFetchTask()
   - Fetches all tasks from API on page load
   - Iterates through tasks and renders each one

3. handleAddTask(e)
   - Prevents default form submission
   - Validates input and creates new task
   - Calls API and updates UI

4. showTaskUI(task)
   - Dynamically creates DOM elements for each task
   - Only creates header section once (optimization)
   - Applies responsive Tailwind CSS classes
   - Appends task cards to container

5. handleTaskActions(e)
   - Single handler for Edit, Save, and Delete actions
   - Uses event.target.innerText to determine action
   - Switches between view and edit modes
   - Handles API calls and DOM updates

TASK CLASS (library.js):
------------------------
Static methods for all HTTP operations:
- Task.get(url)          - Fetch all tasks
- Task.post(url, data)   - Create new task
- Task.put(url, data)    - Update existing task
- Task.delete(url)       - Delete task

All methods use try-catch for error handling and return parsed JSON data.

===============================================================================
                        ERRORS TO PREVENT EARLIER
===============================================================================

1. TYPO IN PROPERTY NAME (CRITICAL BUG):
   ❌ Problem: "calssName" instead of "className"
   📍 Location: In handleTaskActions() Save action (script.js)
   ✅ Fix: Always use "className" for setting CSS classes
   💡 Impact: Styling won't apply when reverting from edit to view mode
   🔍 Note: This typo was present in earlier versions but fixed in current code

2. INPUT VALIDATION - WHITESPACE ONLY:
   ❌ Problem: Accepting whitespace-only input as valid
   📍 Location: handleAddTask() and handleTaskActions() Save action
   ✅ Fix: Use .trim() method before validation
   💡 Example: if (taskInput.value.trim() === "")
   🎯 Lesson: Always sanitize and validate user input

3. DUPLICATE HEADER CREATION:
   ❌ Problem: Creating new header for every task added
   📍 Location: showTaskUI() function
   ✅ Fix: Check if header exists before creating
   💡 Code: let divOne = taskContainer.querySelector(".header-section");
   🚀 Benefit: Prevents duplicate DOM elements and improves performance

4. EVENT LISTENER MEMORY LEAK:
   ❌ Problem: Adding individual listeners to each button
   📍 Common mistake in similar apps
   ✅ Fix: Use event delegation on parent container
   💡 Implementation: taskContainer.addEventListener("click", handleTaskActions)
   🎯 Benefit: Better performance, handles dynamic elements, no memory leaks

5. ASYNC ERROR HANDLING:
   ⚠️ Issue: Not providing user-friendly error messages
   📍 Location: All API calls in Task class
   ✅ Current: try-catch blocks with console.log
   💡 Enhancement: Show alert() or toast notifications for better UX
   🔧 Example: catch(err => alert("Failed to fetch tasks"))

6. API REQUEST WITHOUT VALIDATION:
   ❌ Problem: Sending PUT request with empty string
   📍 Location: handleTaskActions() Save action
   ✅ Fix: Validate newText.trim() before API call
   💡 Code: if (newText === "") { alert(); return; }
   🎯 Lesson: Validate data before making network requests

7. DATA ATTRIBUTE ACCESS - FRAGILE CODE:
   ⚠️ Issue: Using firstChild instead of specific selector
   📍 Location: Delete action - taskElement.firstChild.getAttribute("data-id")
   💡 Risk: Could fail if DOM structure changes (whitespace nodes)
   ✅ Better: Use taskElement.querySelector("p").getAttribute("data-id")
   🔧 Alternative: Store task ID on parent container

8. MISSING NULL CHECKS:
   ⚠️ Potential: No check if querySelector returns null
   📍 Risk: App crashes if expected element doesn't exist
   💡 Prevention: Add defensive checks
   ✅ Example: 
      const taskP = taskElement.querySelector("p");
      if (!taskP) return; // Early exit if element not found

9. FORM SUBMISSION TIMING:
   ⚠️ Issue: e.preventDefault() called after validation
   📍 Location: handleAddTask() function
   ✅ Better: Call e.preventDefault() at the beginning
   💡 Current code order is acceptable but could be improved
   🎯 Best Practice: Prevent default first, then validate

10. MISSING LOADING STATES:
    ⚠️ UX Issue: No feedback during API calls
    📍 All async operations
    💡 Enhancement: Show loading spinner or disable buttons
    ✅ Example: button.disabled = true; (during API call)
    🚀 Improvement: Better user experience for slow networks

11. INLINE STYLES VS CLASSES:
    ⚠️ Observation: Long className strings in JavaScript
    📍 All createElement() sections
    💡 Alternative: Define CSS classes in stylesheet
    ✅ Trade-off: Tailwind utility-first approach is valid
    🎯 Note: Current approach works well with Tailwind

12. NO ESCAPE HANDLING:
    ⚠️ Missing: Cancel edit action with Escape key
    📍 When input is in edit mode
    💡 Enhancement: Add keydown listener for Escape key
    ✅ Implementation: Revert to original text on Escape

===============================================================================
                        DEBUGGING TIPS
===============================================================================

COMMON ISSUES:
1. ❌ Tasks not loading
   🔍 Check browser console for API errors
   🔍 Verify MockAPI endpoint is accessible
   🔍 Inspect Network tab for API request/response
   ✅ Ensure CORS is not blocking requests

2. ❌ Edit/Delete not working
   🔍 Use breakpoints in handleTaskActions()
   🔍 Console.log event.target.innerText
   🔍 Verify task IDs are correctly set
   ✅ Check if event delegation is working

3. ❌ Styling not applied after edit
   🔍 Check for "calssName" typo (should be className)
   🔍 Inspect element in DevTools
   🔍 Verify Tailwind classes are correct
   ✅ Ensure Tailwind CDN is loaded

4. ❌ Duplicate tasks appearing
   🔍 Check if handleFetchTask is called multiple times
   🔍 Verify event listeners aren't duplicated
   ✅ Clear taskContainer before rendering

5. ❌ Empty tasks being created
   🔍 Check validation logic in handleAddTask
   🔍 Verify .trim() is used
   ✅ Add console.log before API call

DEBUGGING WORKFLOW:
1. Open Browser DevTools (F12)
2. Check Console tab for errors
3. Inspect Network tab for API calls
4. Use breakpoints in JavaScript
5. Console.log key variables (taskId, task object)
6. Verify DOM structure with Elements tab
7. Test API endpoints in Postman/Insomnia
8. Check MockAPI dashboard for data
9. Clear browser cache if needed
10. Test in incognito mode to rule out extensions

HELPFUL COMMANDS:
- console.log("Task ID:", taskId)
- console.dir(taskElement) // Inspect DOM element
- JSON.stringify(task, null, 2) // Pretty print object
- taskContainer.innerHTML = "" // Clear container
- location.reload() // Refresh page
