CHAPTER 1 :- Next.js Image Optimization
    
    Next.js provides built-in image optimization using the next/image component to deliver responsive, efficient images and improve performance and Core Web Vitals.

    Supports lazy and eager loading for faster page loads.
    Uses caching and custom loaders for efficient delivery.
    Prevents layout shift by reserving image space.
    Enables priority loading and responsive layouts.

    Note: <Image/> in Next.js is similar to the HTML <img> element as both accept src and alt, but <Image/> adds automatic optimization, lazy loading, and performance benefits.

    Core Web Vitals
        Core Web Vitals are performance metrics that measure the loading speed, responsiveness, and visual stability of a web page. Next.js Image Optimization helps improve these metrics by optimizing how images are loaded and displayed.

        Largest Contentful Paint (LCP): Measures how quickly the largest visible content loads.
        Interaction to Next Paint (INP): Measures how quickly the page responds to user interactions.
        Cumulative Layout Shift (CLS): Measures the visual stability of a page by tracking unexpected layout shifts.

    Image Optimization
        The Image component in Next.js automatically optimizes images added to the application. It also provides various properties to further optimize and control image loading and rendering.

          Property	         Type	  Required	            Description
            src	            string	    Yes	       The path or URL to the image.

            alt	            string	    Yes	       Descriptive text for the image, used for accessibility.

            width	        number	    Yes	       The width of the image in pixels.

            height	        number	    Yes	       The height of the image in pixels.

            quality	        number 
                    (1-100, default: 75) No	       The quality of the optimized image.

            priority	    boolean 
                        (default: false) No	       If true, the image will be considered high priority and preloaded.

            placeholder	    blur,empty	 No	       Specifies a placeholder while the image is loading.

            blurDataURL	    string	     No	       A base64-encoded image used as a placeholder if placeholder="blur".

            unoptimized	    boolean 
                        (default: false) No	       If true, the image will not be optimized.

            loader	        function	 No	       A custom function for loading the image, allowing integration with a third-party image provider.

            onLoadingComplete function	 No	       A callback function that is called when the image has finished loading.

    1. Image loading
        You can control how an image is loaded using the loading prop. The Image component supports two loading strategies:

        eager: Loads image immediately.
        lazy: By default in the image component. Loading until an image is visible. 

        Note: eager is not good for optimization use priority prop instead.
    
    2. Priority Prop
        Use the priority prop to preload above-the-fold images. This helps improve Largest Contentful Paint (LCP).

    3. Image Sizing
        Specifying the width and height props helps prevent Cumulative Layout Shift (CLS) by reserving space for the image before it loads. This improves page stability and user experience.

        If you want the image to automatically fill its parent container instead of specifying fixed dimensions, use the fill prop. The parent element must have position: relative and a defined width and height.
    
    4. ObjectFit Prop
        When using the fill prop, you can use the CSS object-fit property to control how the image is resized within its parent container.

        Common values of object-fit include:

        contain: Scales the image to fit inside the container while maintaining its aspect ratio.
        cover: Fills the container while maintaining the aspect ratio. Parts of the image may be cropped.
        fill: Stretches the image to fill the container, which may distort its aspect ratio.
        none: Displays the image at its original size without resizing.

    5. Placeholder Prop
        It is used as a fallback image when an image is loading. It is also called a temporary alternative or loading indicator. The placeholder indicates that the image is being loaded.

        Placeholder provides two values:
            blur
            empty

CHAPTER 2 :- Role of semantics, sitemap and robots.txt in SEO

    SEO improves a website’s visibility in search engines by helping them understand, crawl, and rank content effectively using tools like semantic HTML, sitemaps, and robots.txt.

        Semantic HTML improves content meaning and accessibility for search engines.
        Sitemaps and robots.txt guide search engines on what to crawl and index.
    
    Semantics in SEO
        Semantic HTML uses descriptive elements to clearly define different sections of a webpage, making the content more readable for assistive technologies and easier for search engines to interpret and categorize accurately.

        Here are some commonly used semantic HTML elements:

        Heading Tags (<h1>–<h6>): Use one <h1> for the main title and subheadings for structure.
        Article (<article>): Wrap standalone content like blogs or news.
        Navigation (<nav>): Define navigation links for better indexing.
        Section (<section>): Group related content blocks.
        Header & Footer (<header>, <footer>): Define top and bottom page areas.
        Alt Text (alt): Describe images for accessibility and SEO.

    Sitemap
        A sitemap is an XML file that lists all the pages of a website. It helps search engines crawl and index your site efficiently.

        Importance of a Sitemap
            Improves Crawlability: Ensures all pages, especially new ones, are discoverable.
            Defines Page Hierarchy: Indicates the relationship between pages.
            Speeds Up Indexing: Helps search engines understand site updates faster.
            Dynamic Sitemap in Next.js
    
    Robots.txt
        The robots.txt file instructs search engine crawlers about which parts of a website they can or cannot access.

        Structure of Robots.txt
            User-Agent: Specifies the crawler (e.g., Googlebot).
            Allow/Disallow: Grants or restricts access to specific paths.
            Sitemap: Points crawlers to the sitemap URL.
            
    Combining Sitemap and Robots.txt in Next.js
        Combining Sitemap and robots.txt in Next.js helps search engines efficiently crawl, understand, and index your website content.

        Steps:
            Create sitemap.js for dynamic sitemaps.
            Add robots.js for robots.txt configuration.
            Test your setup by visiting /sitemap.xml and /robots.txt in the browser.

CHAPTER 3:- Dynamic Metadata for SEO in Next.js

    Metadata helps improve SEO and social media previews by enabling platforms to understand and display page content accurately. Next.js supports dynamic metadata, including Open Graph tags and OG images.

        Improves search engine visibility and ranking.
        Enhances social media previews with accurate titles, descriptions, and images.
    
    Understanding Metadata and Its Role in SEO
        Metadata includes HTML meta tags such as the page title, description, keywords, and OG tags. These tags provide information about your webpage to search engines and social media platforms. Here's what they do:

            Title: Displays the title of the webpage in search results and browser tabs.
            Description: Summarizes the content of the page for search engines.
            OG Tags: Open Graph metadata used to create rich previews on social media.
            Dynamic Metadata: Allows customization of tags for dynamic pages, improving their SEO and social previews.
        
    Challenges with Traditional React Metadata Management
        In earlier React setups or older versions of Next.js, metadata was often managed in the _app.js or layout files. This approach had several drawbacks:

            Client-side rendering delays metadata, making it unavailable during initial crawl.
            Static metadata cannot handle dynamic page-specific content.
            Search engines and social platforms may fail to fetch correct metadata.

    Dynamic OG Images
        Dynamic OG images enhance the preview experience on social platforms by tailoring images to match page content.

    Testing and Validating Metadata
        Testing and validating metadata ensures that search engines correctly read, interpret, and display your page information in search results.

            Social Media Previews: Use tools like Facebook Debugger or Twitter Card Validator to test OG metadata.
            SEO Audits: Use tools like Google Search Console or SEMrush to ensure proper indexing of metadata.

    Best Practices
        Metadata is crucial for SEO and social media visibility.
        Next.js supports static and dynamic metadata via metadata and generateMetadata.
        Dynamic OG images create unique page previews.
        Use accurate metadata with absolute URLs for better SEO.
        Built-in metadata features improve visibility and user engagement.
