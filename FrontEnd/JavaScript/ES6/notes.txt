───────────────────────────────────────────────────────────────────────────
🎯 1.0 FUNCTION TYPES & HOISTING
───────────────────────────────────────────────────────────────────────────

WHAT ARE THE DIFFERENT FUNCTION TYPES?

    1) FUNCTION DECLARATION (Named Functions):
       function greet(name) {
           console.log(`Hello, ${name}!`);
       }
       greet("John");

    2) FUNCTION EXPRESSION (Anonymous or Named):
       const greet = function(name) {
           console.log(`Hello, ${name}!`);
       };
       greet("John");

    3) ARROW FUNCTION (Modern & Short):
       const greet = (name) => {
           console.log(`Hello, ${name}!`);
       };
       greet("John");

    4) NAMED FUNCTION EXPRESSION:
       const greet = function myFunc(name) {
           console.log(`Hello, ${name}!`);
       };
       myFunc("John");  // Can call as myFunc
       greet("John");   // Or as greet

UNDERSTANDING HOISTING:

    What is Hoisting?
    - JavaScript moves function declarations to the TOP of their scope
    - This is called "hoisting"
    - Allows you to call functions BEFORE declaring them!

    FUNCTION DECLARATIONS ARE HOISTED:
    ✅ sayHello();  // Works! Even though it's called BEFORE declaration!

    function sayHello() {
        console.log("Hello!");
    }

    WHY? The interpreter sees it as:
    function sayHello() { ... }  // Moved to top!
    sayHello();

    FUNCTION EXPRESSIONS ARE NOT HOISTED:
    ❌ greet("John");  // Error! Called too early!

    const greet = function(name) {
        console.log(`Hello, ${name}!`);
    };

    WHY? It's treated as a variable assignment, not a function declaration.

    ARROW FUNCTIONS ARE NOT HOISTED:
    ❌ greet("John");  // Error! Same as function expressions

    const greet = (name) => {
        console.log(`Hello, ${name}!`);
    };

KEY DIFFERENCES:

    ┌────────────────────┬───────────┬──────────────┬────────────────┐
    │  Type              │ Hoisted   │ Can access   │ 'this' binding │
    ├────────────────────┼───────────┼──────────────┼────────────────┤
    │ Function Decl.     │ ✅ Yes    │ Before decl. │ Own context    │
    │ Function Expr.     │ ❌ No     │ After decl.  │ Own context    │
    │ Arrow Function     │ ❌ No     │ After decl.  │ Lexical        │
    └────────────────────┴───────────┴──────────────┴────────────────┘

BEST PRACTICES:
    ✅ Use function declarations for main functions
    ✅ Use arrow functions for callbacks and simple operations
    ✅ Use function expressions when you need flexibility
    ✅ Avoid relying on hoisting - declare before using
    ✅ Use const for function expressions (safer than let)

───────────────────────────────────────────────────────────────────────────
🎯 1.1 ARROW FUNCTIONS (=>)
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    A shorter, cooler way to write functions! Instead of writing 
    "function", you just use an arrow (=>). It's like a shortcut!

NORMAL WAY:
    function sayHello() {
        console.log("Hello!");
    }

ARROW WAY (Cooler!):
    const sayHello = () => console.log("Hello!");

WHY USE IT?
    ✅ Less typing! (Lazy programmers love this 😄)
    ✅ Looks cleaner and modern
    ✅ Fixes the confusing "this" problem
    ✅ Great for short functions

WHEN TO USE?
    - When you need a quick function
    - Inside array methods (map, filter, forEach)
    - For callbacks (functions passed to other functions)
    - When you want shorter code

WHERE TO USE?
    - Event listeners
    - Array operations
    - setTimeout/setInterval
    - API calls and promises

COOL FEATURES:

    1) Single Parameter = No Parenthesis Needed!
       const greet = name => console.log(`Hi ${name}!`);
       greet("John"); // Output: Hi John!

    2) Single Return = No Curly Braces or "return" Keyword!
       const add = (a, b) => a + b;
       console.log(add(5, 3)); // Output: 8

    3) Lexical "this" Binding (The Magic Part!)
       - Arrow functions remember their "this" from where they were created
       - Regular functions forget their "this" and get confused!

REAL EXAMPLE - The "this" Problem:

    ❌ BROKEN (Regular Function):
    function Counter() {
        this.count = 0;
        setInterval(function() {
            console.log(this.count++); // "this" is LOST! Gets undefined
        }, 1000);
    }
    new Counter(); // Won't work correctly!

    ✅ FIXED (Arrow Function):
    function Counter() {
        this.count = 0;
        setInterval(() => {
            console.log(this.count++); // "this" is REMEMBERED! Works!
        }, 1000);
    }
    new Counter(); // Output: 0, 1, 2, 3, 4... (Perfect!)

ADVANTAGES:
    ✅ Shorter and cleaner code
    ✅ No "this" confusion - it remembers context
    ✅ Perfect for one-line functions
    ✅ Modern and professional looking

DISADVANTAGES:
    ❌ Can't be used as constructors (no "new" keyword)
    ❌ No "arguments" object
    ❌ Can be confusing for beginners
    ❌ Not good for object methods

KID-FRIENDLY ANALOGY:
    Imagine you're playing a video game. Regular functions are like 
    forgetting which character you were playing when you switch screens. 
    Arrow functions are like a sticky note that reminds you "Hey, you 
    were playing as the knight!" 🛡️

───────────────────────────────────────────────────────────────────────────
🎯 1.2 CALLBACK FUNCTIONS
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    A function you pass to another function, and that function calls it 
    when it's ready! It's like saying "Hey, when you're done, call this!"

SIMPLE EXAMPLE:
    function sayHello(callback) {
        console.log("Hello!");
        callback(); // Calling the callback function
    }

    function sayGoodbye() {
        console.log("Goodbye!");
    }

    sayHello(sayGoodbye);
    // Output: 
    // Hello!
    // Goodbye!

WHY USE IT?
    ✅ Handle tasks that take time (loading files, API calls)
    ✅ Tell your code "Do this AFTER that finishes"
    ✅ Make your code flexible and reusable

WHEN TO USE?
    - Reading files
    - Making network requests
    - Interacting with databases
    - Events (button clicks, page loads)
    - Timers (setTimeout, setInterval)

WHERE TO USE?
    - Event handlers (onclick, addEventListener)
    - Array methods (forEach, map, filter)
    - Asynchronous operations
    - Custom functions that need flexibility

REAL EXAMPLE:
    function addNumbers(a, b, callback) {
        let result = a + b;
        callback(result);
    }

    function displaySum(result) {
        console.log(`The sum is: ${result}`);
    }

    addNumbers(10, 20, displaySum); // Output: The sum is: 30

ADVANTAGES:
    ✅ Handle async operations smoothly
    ✅ Code reusability
    ✅ Flexible - can pass different functions
    ✅ Foundation for understanding Promises

DISADVANTAGES:
    ❌ "Callback Hell" - nested callbacks get messy
    ❌ Hard to read when there are many
    ❌ Difficult error handling
    ❌ Can become confusing quickly

CALLBACK HELL EXAMPLE (Ugly!):
    doSomething(function(result1) {
        doSomethingElse(result1, function(result2) {
            doMoreStuff(result2, function(result3) {
                evenMoreStuff(result3, function(result4) {
                    // This is getting crazy! 😵
                });
            });
        });
    });

KID-FRIENDLY ANALOGY:
    It's like asking your friend to borrow a toy, and saying "When you're 
    done playing with it, give me a call!" The "call" is the callback - 
    they'll contact you when they finish. 📞

───────────────────────────────────────────────────────────────────────────
🎯 1.3 HIGHER ORDER FUNCTIONS
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    A fancy function that either:
    1) Takes a function as a parameter, OR
    2) Returns a function
    
    It's like a super function that can work with other functions!

EXAMPLE 1 - Takes a Function:
    function greet(name, formatter) {
        return formatter(name);
    }

    const uppercase = (name) => name.toUpperCase();
    const lowercase = (name) => name.toLowerCase();

    console.log(greet("John", uppercase)); // Output: JOHN
    console.log(greet("John", lowercase)); // Output: john

EXAMPLE 2 - Returns a Function:
    function multiplier(factor) {
        return function(number) {
            return number * factor;
        };
    }

    const double = multiplier(2);
    const triple = multiplier(3);

    console.log(double(5)); // Output: 10
    console.log(triple(5)); // Output: 15

WHY USE IT?
    ✅ Make code super flexible
    ✅ Avoid repeating yourself
    ✅ Create function factories
    ✅ Work with powerful array methods

WHEN TO USE?
    - Array manipulations (map, filter, reduce)
    - Creating reusable logic
    - Function composition
    - Decorators and middleware

WHERE TO USE?
    - Data processing
    - Event handling systems
    - Functional programming
    - Building utilities

COMMON HIGHER ORDER FUNCTIONS:

    1) map() - Transform each item
       const numbers = [1, 2, 3, 4];
       const doubled = numbers.map(num => num * 2);
       // Output: [2, 4, 6, 8]

    2) filter() - Keep items that match
       const numbers = [1, 2, 3, 4, 5];
       const evens = numbers.filter(num => num % 2 === 0);
       // Output: [2, 4]

    3) reduce() - Combine all items into one
       const numbers = [1, 2, 3, 4];
       const sum = numbers.reduce((total, num) => total + num, 0);
       // Output: 10

ADVANTAGES:
    ✅ Very flexible and powerful
    ✅ Less code duplication
    ✅ Easy to test
    ✅ Foundation of functional programming

DISADVANTAGES:
    ❌ Can be confusing for beginners
    ❌ Sometimes hard to debug
    ❌ Might be overkill for simple tasks

KID-FRIENDLY ANALOGY:
    Imagine a toy factory machine (higher order function) that can change 
    what it makes based on which mold (regular function) you put into it. 
    Same machine, different toys! 🏭🧸

                    📂 SECTION 1.5: ES6 CLASSES
═══════════════════════════════════════════════════════════════════════════

WHAT IS IT?
    Classes are a modern way to create reusable objects with properties 
    and methods. They're like blueprints for creating similar items!
    
    Think of a class like a recipe 📖 - the recipe tells you HOW to make 
    cookies. Every time you follow it, you get the same type of cookies!

WHY USE IT?
    ✅ Cleaner, more organized code
    ✅ Better than constructor functions
    ✅ Easier to understand (OOP style)
    ✅ Fixes 'this' binding issues automatically
    ✅ Supports inheritance (creating sub-classes)
    ✅ Industry standard for modern JavaScript

WHEN TO USE?
    - When you need to create multiple similar objects
    - Building complex applications
    - Organizing code into logical groups
    - Creating reusable components
    - When inheritance is needed

WHERE TO USE?
    - React components (class components)
    - Game development
    - Web applications
    - Any project needing organization

───────────────────────────────────────────────────────────────────────────
🎯 1.5.1 BASIC CLASS STRUCTURE
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    A class has:
    1) constructor() - Runs when you create a new object
    2) methods - Functions that belong to the class
    3) properties - Data that belongs to the class

BASIC SYNTAX:
    class ClassName {
        constructor(parameters) {
            // Initialization code
            this.property = parameter;
        }

        methodName() {
            // Method code
            return something;
        }
    }

    // Create an instance (object from class)
    const object = new ClassName(arguments);
    object.methodName();

REAL EXAMPLE - Create a User Class:

    class User {
        // Constructor - Runs when you create new User
        constructor(name, email, age) {
            this.name = name;
            this.email = email;
            this.age = age;
        }

        // Method 1 - Display info
        displayInfo() {
            console.log(`Name: ${this.name}, Email: ${this.email}`);
        }

        // Method 2 - Check if adult
        isAdult() {
            return this.age >= 18;
        }

        // Method 3 - Have a birthday
        birthday() {
            this.age++;
            console.log(`Happy birthday! Now ${this.age} years old!`);
        }
    }

    // Create instances
    const user1 = new User("Alice", "alice@example.com", 25);
    const user2 = new User("Bob", "bob@example.com", 17);

    user1.displayInfo();        // Output: Name: Alice, Email: alice@example.com
    user1.isAdult();            // Output: true
    user2.isAdult();            // Output: false

    user1.birthday();           // Output: Happy birthday! Now 26 years old!

KEY POINTS:
✓ Constructor runs ONCE when you create object with 'new'
✓ 'this' always refers to the current object (automatically!)
✓ Methods are functions that live inside the class
✓ Call methods with dot notation: object.method()

───────────────────────────────────────────────────────────────────────────
🎯 1.5.2 'THIS' BINDING FIXED BY CLASSES
───────────────────────────────────────────────────────────────────────────

WHAT IS THE PROBLEM?
    In regular functions, 'this' can get confused. But classes FIX this!

❌ BROKEN - Regular Function Constructor:

    function Counter() {
        this.count = 0;
        // Problem: 'this' inside setTimeout is lost!
        setInterval(function() {
            console.log(this.count++);  // undefined! ❌
        }, 1000);
    }

    new Counter();  // Doesn't work correctly

✅ FIXED - Using Arrow Function in Regular Constructor:

    function CounterFixed() {
        this.count = 0;
        // Arrow function preserves 'this'
        setInterval(() => {
            console.log(this.count++);  // Works! ✅
        }, 1000);
    }

    new CounterFixed();

✅✅ BEST - Using ES6 Class:

    class Counter {
        constructor() {
            this.count = 0;
        }

        startCounting() {
            setInterval(() => {
                console.log(this.count++);  // Always works! ✅✅
            }, 1000);
        }
    }

    new Counter().startCounting();
    // Output: 0, 1, 2, 3, 4...

WHY CLASSES ARE BETTER:
✓ 'this' is handled correctly automatically
✓ No confusion or binding issues
✓ Much cleaner syntax
✓ More intuitive for beginners

───────────────────────────────────────────────────────────────────────────
🎯 1.5.3 CLASS INHERITANCE (Advanced)
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    Inheritance lets you create a new class based on an existing class.
    The new class inherits properties and methods from the parent class!

    Think of it like DNA 🧬:
    - Parent class = your parents' DNA
    - Child class = inherits traits from parents

SYNTAX:
    class ParentClass {
        method1() { }
    }

    class ChildClass extends ParentClass {
        method2() { }
    }

EXAMPLE - Animal Classes:

    // Parent class
    class Animal {
        constructor(name) {
            this.name = name;
        }

        speak() {
            console.log(`${this.name} makes a sound`);
        }
    }

    // Child class that inherits from Animal
    class Dog extends Animal {
        constructor(name, breed) {
            super(name);  // Call parent constructor
            this.breed = breed;
        }

        // Override parent method
        speak() {
            console.log(`${this.name} barks! Woof woof!`);
        }
    }

    // Create instances
    const dog = new Dog("Buddy", "Golden Retriever");
    dog.speak();  // Output: Buddy barks! Woof woof!
    console.log(dog.breed);  // Output: Golden Retriever

KEY WORDS:
    extends - Creates a child class from parent class
    super() - Calls parent class constructor
    super.method() - Calls parent method

───────────────────────────────────────────────────────────────────────────
🎯 1.5.4 STATIC METHODS (Class-Level Methods)
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    Static methods belong to the CLASS itself, not to individual objects.
    You call them on the class name, not on instances.

EXAMPLE:

    class MathHelper {
        // Static method
        static add(a, b) {
            return a + b;
        }

        // Regular method
        multiply(a, b) {
            return a * b;
        }
    }

    // Call static method ON the class
    console.log(MathHelper.add(5, 3));  // Output: 8

    // Regular methods need an instance
    const helper = new MathHelper();
    console.log(helper.multiply(5, 3));  // Output: 15

    // This WON'T work:
    console.log(MathHelper.multiply(5, 3));  // Error!

WHEN TO USE:
    - Utility functions (Math.max(), etc.)
    - Factory methods
    - Constants

EXAMPLE - User Factory:

    class UserFactory {
        static createAdmin(name) {
            return { name, role: 'admin', permissions: ['read', 'write', 'delete'] };
        }

        static createGuest(name) {
            return { name, role: 'guest', permissions: ['read'] };
        }
    }

    const admin = UserFactory.createAdmin("John");
    const guest = UserFactory.createGuest("Alice");

    console.log(admin);   // { name: 'John', role: 'admin', ... }
    console.log(guest);   // { name: 'Alice', role: 'guest', ... }

───────────────────────────────────────────────────────────────────────────
🎯 1.5.5 GETTERS AND SETTERS
───────────────────────────────────────────────────────────────────────────

WHAT ARE THEY?
    Getters and setters allow you to control how properties are accessed 
    and modified. It's like having gates 🚪 for your data!

GETTERS - Get property values (looks like accessing property):
    get propertyName() {
        return this._property;
    }

SETTERS - Set property values (looks like normal assignment):
    set propertyName(value) {
        this._property = value;
    }

EXAMPLE:

    class Person {
        constructor(firstName, lastName) {
            this._firstName = firstName;
            this._lastName = lastName;
        }

        // Getter - Notice: NO parentheses when calling!
        get fullName() {
            return `${this._firstName} ${this._lastName}`;
        }

        // Setter - Notice: NO parentheses when setting!
        set fullName(name) {
            const [first, last] = name.split(' ');
            this._firstName = first;
            this._lastName = last;
        }
    }

    const person = new Person("John", "Doe");
    
    console.log(person.fullName);      // Output: John Doe (uses getter)
    person.fullName = "Jane Smith";    // Uses setter
    console.log(person.fullName);      // Output: Jane Smith

KEY POINTS:
✓ Getters look like accessing a property (no parentheses!)
✓ Setters look like assigning a value (no parentheses!)
✓ Validation can be added in setters
✓ Encapsulation - hide internal logic

EXAMPLE WITH VALIDATION:

    class BankAccount {
        constructor(balance) {
            this._balance = balance;
        }

        get balance() {
            return this._balance;
        }

        set balance(amount) {
            if (amount < 0) {
                console.log("Balance cannot be negative!");
                return;
            }
            this._balance = amount;
        }

        deposit(amount) {
            this.balance += amount;  // Uses setter
        }
    }

    const account = new BankAccount(1000);
    console.log(account.balance);  // Output: 1000 (uses getter)
    account.balance = 500;         // Uses setter
    account.balance = -100;        // Output: Balance cannot be negative!

───────────────────────────────────────────────────────────────────────────
🎯 1.5.6 CLASS BEST PRACTICES & TIPS
───────────────────────────────────────────────────────────────────────────

NAMING CONVENTIONS:
    ✅ Class names: PascalCase (start with capital letter)
       class UserAccount { }
       class ShoppingCart { }

    ✅ Property names: camelCase (start with lowercase)
       this.firstName = name;
       this.emailAddress = email;

    ✅ Private properties: underscore prefix
       this._password = password;  // Hint: "don't touch me from outside!"

COMMON MISTAKES:

    1) Forgetting 'new' keyword:
       ❌ const user = User("John");    // Error!
       ✅ const user = new User("John"); // Correct!

    2) Not calling super() in child class:
       ❌ class Dog extends Animal {
              constructor(name, breed) {
                  this.breed = breed;
              }
          }
       
       ✅ class Dog extends Animal {
              constructor(name, breed) {
                  super(name);
                  this.breed = breed;
              }
          }

    3) Confusing methods and getters:
       // These are different!
       this.getName()      // Method - needs parentheses
       this.name           // Getter - looks like property

    4) Too much inheritance:
       ❌ Don't create deep chains: 
          Animal -> Mammal -> Dog -> Daschund -> GoldenRetriever
       
       ✅ Keep it simple: Usually 1-2 levels max

ADVANCED TIP - Composition Over Inheritance:
    Instead of deep inheritance chains, combine multiple classes:

    // Bad: Deep inheritance
    class Animal { }
    class Mammal extends Animal { }
    class Dog extends Mammal { }

    // Good: Mix and match features
    class Swimmer {
        swim() { console.log("Swimming"); }
    }

    class Runner {
        run() { console.log("Running"); }
    }

    class Dog {
        constructor() {
            this.swimmer = new Swimmer();
            this.runner = new Runner();
        }
    }

ADVANTAGES OF CLASSES:
    ✅ Organized and clean code
    ✅ Reusable templates for objects
    ✅ Easy inheritance
    ✅ 'this' binding works correctly
    ✅ Industry standard
    ✅ Similar to other languages (Python, Java, C++)
    ✅ Great for large projects
    ✅ Encapsulation and data hiding

DISADVANTAGES:
    ❌ Can be overkill for simple scripts
    ❌ Might be confusing for beginners
    ❌ JavaScript isn't truly classical OOP
    ❌ Not needed for functional programming

REAL-WORLD COMPARISON:

    ❌ OLD WAY (Constructor Functions):
    function User(name, email) {
        this.name = name;
        this.email = email;
    }

    User.prototype.displayInfo = function() {
        console.log(this.name);
    };

    new User("John", "john@example.com");

    ✅ NEW WAY (ES6 Classes):
    class User {
        constructor(name, email) {
            this.name = name;
            this.email = email;
        }

        displayInfo() {
            console.log(this.name);
        }
    }

    new User("John", "john@example.com");

MUCH CLEANER! 🎉

KID-FRIENDLY ANALOGY:
    Classes are like toy molds 🏭:
    
    - Class = Mold (the design)
    - Instance = Toy (what comes out of mold)
    - Constructor = What happens first when toy is made
    - Method = Something the toy can DO
    - Inheritance = Making a similar toy based on another mold
    
    You can use the SAME mold to make MANY toys quickly!

═══════════════════════════════════════════════════════════════════════════
                    📂 SECTION 2: PROMISES
═══════════════════════════════════════════════════════════════════════════

WHAT IS IT?
    A Promise is JavaScript's way of saying: "I PROMISE to give you an 
    answer later!" It's used when something takes time to complete.

    Think of it like ordering pizza 🍕:
    - You order (create promise)
    - You wait (pending)
    - Pizza arrives (resolved) OR something went wrong (rejected)

WHY USE IT?
    ✅ Better than callback hell
    ✅ Cleaner code for async operations
    ✅ Better error handling
    ✅ Can chain multiple operations easily

WHEN TO USE?
    - API calls (fetching data from internet)
    - File operations
    - Database queries
    - Any operation that takes time

WHERE TO USE?
    - Loading data from servers
    - Processing images
    - Animations
    - Timer functions

PROMISE STATES:
    1) Pending ⏳ - Still working on it
    2) Fulfilled ✅ - Success! Here's your data
    3) Rejected ❌ - Oops! Something went wrong

BASIC STRUCTURE:
    const myPromise = new Promise((resolve, reject) => {
        // Do something that takes time
        let success = true;
        
        if (success) {
            resolve("Success! Here's your data!"); // Everything went well
        } else {
            reject("Error! Something went wrong!"); // Something failed
        }
    });

    // Using the promise:
    myPromise
        .then(data => console.log(data))    // If success
        .catch(err => console.log(err));    // If error

REAL EXAMPLE - Countdown Timer:
    function countdown(number) {
        return new Promise((resolve, reject) => {
            if (number < 0) {
                reject("Number can't be negative!");
            } else {
                setTimeout(() => {
                    resolve(number);
                }, 1000);
            }
        });
    }

    countdown(3)
        .then(num => { 
            console.log(num); // Output: 3
            return countdown(2);
        })
        .then(num => {
            console.log(num); // Output: 2
            return countdown(1);
        })
        .then(num => {
            console.log(num); // Output: 1
            console.log("Blast off! 🚀");
        })
        .catch(err => console.log(err));

PROMISE CHAINING:
    - You can connect multiple .then() calls
    - Each .then() receives data from previous one
    - Much cleaner than nested callbacks!

ADVANTAGES:
    ✅ Escapes callback hell
    ✅ Better error handling with .catch()
    ✅ Can chain multiple operations
    ✅ More readable and maintainable
    ✅ Can run multiple promises together

DISADVANTAGES:
    ❌ Can still get messy with many .then()
    ❌ Harder to understand than simple functions
    ❌ No way to cancel once started
    ❌ Debugging can be tricky

PROMISE HELPERS:

    1) Promise.all() - Wait for ALL promises
       Promise.all([promise1, promise2, promise3])
           .then(results => console.log(results));

    2) Promise.race() - Use the FASTEST promise
       Promise.race([promise1, promise2])
           .then(result => console.log(result));

KID-FRIENDLY ANALOGY:
    You ask your mom for cookies. She says "PROMISE, I'll bake them!" 
    (Promise created). While baking (pending), you wait. Finally, either 
    she gives you cookies (resolved) or burned them (rejected). But you 
    KNOW you'll get an answer! 🍪

                    📂 SECTION 3: FETCH API
═══════════════════════════════════════════════════════════════════════════

WHAT IS IT?
    Fetch is a modern way to GET or SEND data from/to the internet!
    It's like your browser's delivery service 📦 - it fetches things 
    from websites for you!

WHY USE IT?
    ✅ Built into modern browsers (no libraries needed!)
    ✅ Returns Promises (cleaner than old methods)
    ✅ Easy to use

WHEN TO USE?

    - Sending form data to a server

WHERE TO USE?
    - Web applications
    - Single Page Applications (SPAs)
    - Real-time data updates
    - User authentication

BASIC SYNTAX:
    fetch(url)
        .then(response => response.json())  // Convert to JavaScript
        .then(data => console.log(data))    // Use the data
        .catch(error => console.log(error)); // Handle errors

FETCH DIFFERENT DATA TYPES:

    1) FETCH TEXT FILE:
       fetch("./data.txt")
           .then(response => response.text())
           .then(text => console.log(text));

    2) FETCH JSON FILE:
       fetch("./users.json")
           .then(response => response.json())
           .then(data => console.log(data));

    3) FETCH FROM API:
       fetch("https://api.example.com/users")
           .then(response => response.json())
           .then(users => console.log(users));

    function getUsers() {
        fetch("https://jsonplaceholder.typicode.com/users")
            .then(response => response.json())
            .then(users => {

                    console.log(`Name: ${user.name}`);
                    console.log(`Email: ${user.email}`);
                    console.log(`City: ${user.address.city}`);
                });
            })
            .catch(err => console.log("Error:", err));
    }

TWO-STEP PROCESS:
    Step 1: Get the response
        .then(response => response.json())
    
    Step 2: Get the actual data
        .then(data => { /* use data */ })

WHY TWO STEPS?
    - First step gets the "package" from the server
    - Second step "opens the package" to get the data inside

ADVANTAGES:
    ✅ Modern and promise-based
    ✅ Built into browsers (no installation)
    ✅ Cleaner than old XMLHttpRequest
    ✅ Works with async/await
    ✅ Very flexible

DISADVANTAGES:
    ❌ Not supported in very old browsers
    ❌ No timeout feature built-in
    ❌ Doesn't reject on HTTP errors (like 404)
    ❌ Can't track upload progress easily

COMMON RESPONSE METHODS:
    - response.text()  → Get as plain text
    - response.json()  → Get as JavaScript object
    - response.blob()  → Get as file/image
    - response.formData() → Get form data

ERROR HANDLING:
    fetch("https://api.example.com/data")
        .then(response => {
            if (!response.ok) {
                throw new Error("HTTP Error: " + response.status);
            }
            return response.json();
        })
        .then(data => console.log(data))
        .catch(error => console.log("Error:", error));

    class EasyHttp {

        get(url) {

                    .catch(err => reject(err));

        post(url, data) {
            return new Promise((resolve, reject) => {
                fetch(url, {
                    method: "POST",
                    headers: {"Content-Type": "application/json"},
                    body: JSON.stringify(data)
                })
                .then(res => res.json())
                .then(data => resolve(data))
                .catch(err => reject(err));
            });
        }

        // PUT
        put(url, data) {
            return new Promise((resolve, reject) => {
                fetch(url, {
                    method: "PUT",
                    headers: {"Content-Type": "application/json"},
                    body: JSON.stringify(data)
                })
                .then(res => res.json())
                .then(data => resolve(data))
                .catch(err => reject(err));
            });
        }

        // DELETE
        delete(url) {
            return new Promise((resolve, reject) => {
                fetch(url, {
                    method: "DELETE",
                    headers: {"Content-Type": "application/json"}
                })
                .then(res => res.json())
                .then(data => resolve(data))
                .catch(err => reject(err));
            });
        }
    }

                    � SECTION 5: ASYNC/AWAIT
═══════════════════════════════════════════════════════════════════════════

WHAT IS IT?
    Async/Await is the NEWEST and CLEANEST way to handle Promises!
    It makes asynchronous code look and behave like synchronous code.
    
    Think of it as "Promise's Best Friend" - it makes working with 
    Promises super easy and readable! 😎

    Two Keywords:
    1) async  - Makes a function return a Promise
    2) await  - Waits for a Promise to finish (can ONLY be used inside 
                async functions)

WHY USE IT?
    ✅ Makes code look like normal, step-by-step code
    ✅ Much cleaner than .then() chains
    ✅ Easier to read and understand
    ✅ Better error handling with try/catch
    ✅ The MODERN standard for handling promises

WHEN TO USE?
    - Fetching data from APIs
    - Reading files
    - Database operations
    - Any asynchronous operations
    - When you want cleaner code than .then()

WHERE TO USE?
    - Modern web applications
    - Server-side JavaScript (Node.js)
    - API integrations
    - Anywhere you're using Promises

BASIC STRUCTURE:

    ❌ OLD WAY (Using .then()):
    function getUser() {
        fetch("https://api.example.com/user")
            .then(response => response.json())
            .then(data => console.log(data))
            .catch(err => console.log(err));
    }

    ✅ NEW WAY (Using async/await):
    async function getUser() {
        try {
            const response = await fetch("https://api.example.com/user");
            const data = await response.json();
            console.log(data);
        } catch (err) {
            console.log(err);
        }
    }

THE "async" KEYWORD:
    - Put it before a function
    - Makes the function automatically return a Promise
    - Even if you return a regular value, it wraps it in a Promise!

    async function sayHello() {
        return "Hello!";  // This becomes Promise.resolve("Hello!")
    }

    sayHello().then(msg => console.log(msg)); // Output: Hello!

THE "await" KEYWORD:
    - Can ONLY be used inside async functions
    - Makes JavaScript WAIT for the Promise to finish
    - Returns the resolved value of the Promise

    const response = await fetch(url);  // Wait for fetch to complete

REAL EXAMPLE - Fetching User Data:

    const API_URL = "https://jsonplaceholder.typicode.com/users";

    async function fetchUserData() {
        try {
            // Wait for the server response
            const response = await fetch(API_URL);
            
            // Wait for converting response to JSON
            const data = await response.json();
            
            // Now we have the data!
            data.forEach(user => {
                console.log(`Name: ${user.name}`);
                console.log(`Email: ${user.email}`);
            });
        } catch (error) {
            console.log("Error:", error);
        }
    }

    fetchUserData();

HANDLING MULTIPLE PROMISES:

    Example 1 - Sequential (One after another):
    async function getTwoUsers() {
        const user1 = await fetch("https://api.example.com/user/1");
        const data1 = await user1.json();
        
        const user2 = await fetch("https://api.example.com/user/2");
        const data2 = await user2.json();
        
        console.log(data1, data2);
    }

    Example 2 - Parallel (At the same time - FASTER!):
    async function getTwoUsersParallel() {
        const [user1, user2] = await Promise.all([
            fetch("https://api.example.com/user/1"),
            fetch("https://api.example.com/user/2")
        ]);
        
        const data1 = await user1.json();
        const data2 = await user2.json();
        
        console.log(data1, data2);
    }

ERROR HANDLING - try/catch:

    async function getUserData() {
        try {
            // Code that might fail
            const response = await fetch("https://api.example.com/user");
            
            if (!response.ok) {
                throw new Error(`HTTP Error: ${response.status}`);
            }
            
            const data = await response.json();
            console.log(data);
            
        } catch (error) {
            // This runs if anything goes wrong
            console.log("Something went wrong:", error);
        } finally {
            // This ALWAYS runs (optional)
            console.log("Operation completed");
        }
    }

REAL WORLD EXAMPLE - Complete Flow:

    async function processUserData() {
        try {
            console.log("Fetching user data...");
            
            // Step 1: Get user
            const userResponse = await fetch("https://api.example.com/user/1");
            const user = await userResponse.json();
            console.log("User:", user.name);
            
            // Step 2: Get user's posts
            const postsResponse = await fetch(`https://api.example.com/user/${user.id}/posts`);
            const posts = await postsResponse.json();
            console.log("Posts:", posts.length);
            
            // Step 3: Get comments for first post
            const commentsResponse = await fetch(`https://api.example.com/posts/${posts[0].id}/comments`);
            const comments = await commentsResponse.json();
            console.log("Comments:", comments.length);
            
            return { user, posts, comments };
            
        } catch (error) {
            console.log("Error:", error.message);
            return null;
        }
    }

    processUserData();

COMPARISON - Promise vs Async/Await:

    ❌ WITH PROMISES (Messy with many .then()):
    function getDataPromise() {
        fetch(url)
            .then(response => response.json())
            .then(data => {
                return processData(data);
            })
            .then(processed => {
                return saveData(processed);
            })
            .then(result => {
                console.log(result);
            })
            .catch(err => console.log(err));
    }

    ✅ WITH ASYNC/AWAIT (Clean and clear!):
    async function getDataAsync() {
        try {
            const response = await fetch(url);
            const data = await response.json();
            const processed = await processData(data);
            const result = await saveData(processed);
            console.log(result);
        } catch (err) {
            console.log(err);
        }
    }

IMPORTANT RULES:

    1) "await" can ONLY be used inside "async" functions
       ❌ const data = await fetch(url);  // Error!
       ✅ async function getData() {
              const data = await fetch(url);  // Works!
          }

    2) "async" functions ALWAYS return a Promise
       async function test() {
           return 5;  // Actually returns Promise that resolves to 5
       }

    3) Always use try/catch for error handling
       async function getData() {
           try {
               const data = await fetch(url);
           } catch (err) {
               console.log(err);  // Handle errors
           }
       }

ADVANTAGES:
    ✅ Code looks cleaner and more readable
    ✅ Feels like writing normal, synchronous code
    ✅ Easier to debug than Promise chains
    ✅ Better error handling with try/catch
    ✅ Can use regular loops and conditionals easily
    ✅ Avoid "then" callback hell
    ✅ Industry standard for modern JavaScript
    ✅ Works perfectly with Promise.all() for parallel operations

DISADVANTAGES:
    ❌ Can only use "await" inside "async" functions
    ❌ Not supported in very old browsers (need transpiler)
    ❌ Can accidentally make code slower if not using Promise.all()
    ❌ Still need to understand Promises to use it well
    ❌ Requires try/catch for every async function
    ❌ Easy to forget "await" keyword (leads to bugs)

COMMON MISTAKES:

    1) Forgetting "await":
       ❌ const data = fetch(url);  // Returns Promise, not data!
       ✅ const data = await fetch(url);  // Returns actual data

    2) Forgetting "async":
       ❌ function getData() {
              const data = await fetch(url);  // Error!
          }
       ✅ async function getData() {
              const data = await fetch(url);  // Works!
          }

    3) Not using try/catch:
       ❌ async function getData() {
              const data = await fetch(url);  // If this fails, crash!
          }
       ✅ async function getData() {
              try {
                  const data = await fetch(url);
              } catch (err) {
                  console.log(err);  // Handles error
              }
          }

    4) Making sequential calls when they could be parallel:
       ❌ SLOW (Waits for each one):
       const user1 = await fetch("url1");
       const user2 = await fetch("url2");

       ✅ FAST (Gets both at once):
       const [user1, user2] = await Promise.all([
           fetch("url1"),
           fetch("url2")
       ]);

COOL TRICKS:

    1) Top-level await (Modern JavaScript):
       // No need to wrap in async function!
       const data = await fetch(url);

    2) Async Arrow Functions:
       const getUser = async () => {
           const response = await fetch(url);
           return response.json();
       };

    3) Async IIFE (Immediately Invoked Function Expression):
       (async () => {
           const data = await fetch(url);
           console.log(data);
       })();

KID-FRIENDLY ANALOGY:
    Imagine you're ordering food at a restaurant 🍽️:
    
    Without await: "Give me food!" *walks away before it's ready*
    
    With await: "Give me food!" *waits at table until food arrives*
    
    Async/await is like telling the waiter: "I'll WAIT here until my 
    food is ready, and THEN I'll eat it!" You don't run away before 
    getting your meal! 😊

                    📂 SECTION 6: DESTRUCTURING
═══════════════════════════════════════════════════════════════════════════

WHAT IS IT?
    Destructuring is a fancy way to UNPACK values from arrays or 
    properties from objects into separate variables!
    
    Think of it like opening a gift box 🎁 and taking out each item 
    one by one, giving each item its own special place!

    Two Types:
    1) Array Destructuring   - Unpacking arrays [...]
    2) Object Destructuring  - Unpacking objects {...}

WHY USE IT?
    ✅ Write less code!
    ✅ Makes code cleaner and easier to read
    ✅ Extract multiple values in one line
    ✅ Swap variables easily
    ✅ Extract data from complex structures

WHEN TO USE?
    - When working with API responses
    - Extracting values from objects/arrays
    - Function parameters
    - Swapping variables
    - Working with React (props, state)

WHERE TO USE?
    - Modern JavaScript applications
    - React components (very common!)
    - Working with JSON data
    - Function return values
    - Module imports

───────────────────────────────────────────────────────────────────────────
🎯 6.1 ARRAY DESTRUCTURING
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    Extracting values from an array and assigning them to variables.

❌ OLD WAY (Boring!):
    const colors = ["red", "green", "blue"];
    const color1 = colors[0];
    const color2 = colors[1];
    const color3 = colors[2];

✅ NEW WAY (Cool!):
    const colors = ["red", "green", "blue"];
    const [color1, color2, color3] = colors;
    
    console.log(color1);  // Output: red
    console.log(color2);  // Output: green
    console.log(color3);  // Output: blue

BASIC EXAMPLES:

    1) Simple Destructuring:
       const numbers = [1, 2, 3];
       const [a, b, c] = numbers;
       console.log(a, b, c);  // Output: 1 2 3

    2) Skip Elements:
       const numbers = [1, 2, 3, 4, 5];
       const [first, , third] = numbers;  // Skip second
       console.log(first, third);  // Output: 1 3

    3) Default Values:
       const numbers = [1];
       const [a, b = 10] = numbers;
       console.log(a, b);  // Output: 1 10

    4) Swap Variables (Magic!):
       let x = 1;
       let y = 2;
       [x, y] = [y, x];  // Swap!
       console.log(x, y);  // Output: 2 1

    5) Rest Operator (...):
       const numbers = [1, 2, 3, 4, 5];
       const [first, second, ...rest] = numbers;
       console.log(first);    // Output: 1
       console.log(second);   // Output: 2
       console.log(rest);     // Output: [3, 4, 5]

    6) Nested Array Destructuring:
       const nested = [1, [2, 3], 4];
       const [a, [b, c], d] = nested;
       console.log(a, b, c, d);  // Output: 1 2 3 4

REAL EXAMPLE - Split Function Return:
    function getCoordinates() {
        return [40.7128, -74.0060];  // Latitude, Longitude
    }

    const [lat, lng] = getCoordinates();
    console.log(`Latitude: ${lat}`);   // Output: Latitude: 40.7128
    console.log(`Longitude: ${lng}`);  // Output: Longitude: -74.0060

🎯 6.2 OBJECT DESTRUCTURING

WHAT IS IT?
    Extracting properties from an object and assigning them to variables.

BASIC EXAMPLES:

       const { name, age } = user;
       console.log(name, age);  // Output: Alice 25

    2) Rename Variables:
       const user = { name: "Alice", age: 25 };

       const { name, age, ...others } = person;
       console.log(name, age);     // Output: John 30
       console.log(others);        // Output: { city: "NYC", job: "Developer" }

    6) Destructuring in Function Parameters:
       function greet({ name, age }) {

       }

    // Imagine this comes from an API

        status,

REAL EXAMPLE - Function with Object Parameter:

    // ❌ OLD WAY:
    function displayUser(user) {
        console.log(user.name);
        console.log(user.age);
        console.log(user.email);

                    📂 SECTION 7: REST & SPREAD OPERATORS (...)
═══════════════════════════════════════════════════════════════════════════

One Tip -> Left la ... irundha 'rest' operator. Idhayea Right side la irundha ... 'spread' operator

WHAT ARE THEY?
    Both use the same three dots (...) but do OPPOSITE things!
    
    🎯 SPREAD (...) = EXPANDS/SPREADS things out
    Think: Spreading butter on bread 🧈 → spreading it OUT
    
    🎯 REST (...) = COLLECTS/GATHERS things together
    Think: Resting items in a basket 🧺 → putting them TOGETHER

WHY USE THEM?
    ✅ Write cleaner, shorter code
    ✅ Copy arrays/objects easily (immutability!)
    ✅ Combine multiple arrays/objects
    ✅ Handle flexible function parameters
    ✅ Essential for modern JavaScript and React

WHEN TO USE?
    - Copying arrays or objects
    - Merging data structures
    - Function arguments (variable number of params)
    - Creating immutable updates (React/Redux)
    - Array/object manipulation

WHERE TO USE?
    - Modern JavaScript applications
    - React state management (very important!)
    - API data manipulation
    - Function definitions
    - Array and object operations

───────────────────────────────────────────────────────────────────────────
🎯 7.1 SPREAD OPERATOR (...)
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    Spread operator EXPANDS an array or object into individual elements.
    It's like unpacking a suitcase and laying everything out! 🧳

✨ SPREAD WITH ARRAYS:

    1) Copying an Array:
       ❌ OLD WAY:
       const original = [1, 2, 3];
       const copy = original;  // Danger! Same reference!
       copy.push(4);
       console.log(original);  // Output: [1, 2, 3, 4] - Changed! 😱

       ✅ NEW WAY (Spread):
       const original = [1, 2, 3];
       const copy = [...original];  // New array! Safe! ✅
       copy.push(4);
       console.log(original);  // Output: [1, 2, 3] - Unchanged! 🎉
       console.log(copy);      // Output: [1, 2, 3, 4]

    2) Combining Arrays:
       const fruits = ["apple", "banana"];
       const veggies = ["carrot", "broccoli"];
       
       const food = [...fruits, ...veggies];
       console.log(food);
       // Output: ["apple", "banana", "carrot", "broccoli"]

    3) Adding Elements:
       const numbers = [2, 3, 4];
       const moreNumbers = [1, ...numbers, 5, 6];
       console.log(moreNumbers);  // Output: [1, 2, 3, 4, 5, 6]

    4) Spreading Strings:
       const word = "Hello";
       const letters = [...word];
       console.log(letters);  // Output: ["H", "e", "l", "l", "o"]

    5) Math Operations:
       const numbers = [5, 12, 8, 3, 20];
       console.log(Math.max(...numbers));  // Output: 20
       console.log(Math.min(...numbers));  // Output: 3

    6) Passing Array as Function Arguments:
       function sum(a, b, c) {
           return a + b + c;
       }
       
       const numbers = [1, 2, 3];
       console.log(sum(...numbers));  // Output: 6
       // Same as: sum(1, 2, 3)

✨ SPREAD WITH OBJECTS:

    1) Copying an Object:
       ❌ OLD WAY:
       const original = { name: "John", age: 30 };
       const copy = original;  // Danger! Same reference!
       copy.age = 31;
       console.log(original.age);  // Output: 31 - Changed! 😱

       ✅ NEW WAY (Spread):
       const original = { name: "John", age: 30 };
       const copy = { ...original };  // New object! Safe! ✅
       copy.age = 31;
       console.log(original.age);  // Output: 30 - Unchanged! 🎉
       console.log(copy.age);      // Output: 31

    2) Merging Objects:
       const person = { name: "Alice", age: 25 };
       const job = { title: "Developer", company: "TechCo" };
       
       const employee = { ...person, ...job };
       console.log(employee);
       // Output: { name: "Alice", age: 25, title: "Developer", company: "TechCo" }

    3) Overriding Properties:
       const user = { name: "John", age: 30, city: "NYC" };
       const updatedUser = { ...user, age: 31 };  // Update age
       console.log(updatedUser);
       // Output: { name: "John", age: 31, city: "NYC" }

    4) Adding New Properties:
       const user = { name: "Alice", age: 25 };
       const userWithEmail = { ...user, email: "alice@example.com" };
       console.log(userWithEmail);
       // Output: { name: "Alice", age: 25, email: "alice@example.com" }

    5) Conditional Properties:
       const includeEmail = true;
       const user = {
           name: "John",
           age: 30,
           ...(includeEmail && { email: "john@example.com" })
       };
       console.log(user);
       // Output: { name: "John", age: 30, email: "john@example.com" }

REAL EXAMPLE - React State Update (Immutability!):

🎯 7.2 REST OPERATOR (...)

WHAT IS IT?
    Rest operator COLLECTS multiple elements into a single array/object.

       const numbers = [1, 2, 3, 4, 5];

       console.log(second);  // Output: 2
       console.log(rest);    // Output: [3, 4, 5]

       function sum(...numbers) {
           return numbers.reduce((total, num) => total + num, 0);

       console.log(sum(1, 2, 3, 4, 5));     // Output: 15
       console.log(sum(10, 20, 30, 40));    // Output: 100

       function greet(greeting, ...names) {
           return `${greeting} ${names.join(', ')}!`;
       }
       
       console.log(greet("Hello", "Alice", "Bob", "Charlie"));
       // Output: Hello Alice, Bob, Charlie!

    4) Practical Example - Shopping Cart:
       function addToCart(userId, ...items) {

🎯 7.3 SPREAD VS REST - THE KEY DIFFERENCE!
───────────────────────────────────────────────────────────────────────────

🔍 HOW TO TELL THEM APART?

    POSITION MATTERS! 🎯

    ✨ SPREAD (Right side of =, in function calls):
       const arr = [1, 2, 3];
       const newArr = [...arr];        // SPREAD - unpacks array
       console.log(...arr);            // SPREAD - unpacks for console
       Math.max(...arr);               // SPREAD - unpacks for function

    ✨ REST (Left side of =, in function parameters):
       const [first, ...rest] = arr;   // REST - collects into array
       function sum(...nums) { }       // REST - collects arguments

VISUAL COMPARISON:

    ┌─────────────────────────────────────────────────────────────────────┐
    │                     SPREAD vs REST                                  │
    ├──────────────────┬──────────────────────┬──────────────────────────┤
    │  Feature         │  SPREAD (...)        │  REST (...)              │
    ├──────────────────┼──────────────────────┼──────────────────────────┤
    │  Purpose         │  EXPAND/UNPACK       │  COLLECT/GATHER          │
    │  Direction       │  One → Many          │  Many → One              │
    │  Position        │  Right side of =     │  Left side of =          │
    │  Used In         │  Function calls      │  Function parameters     │
    │                  │  Array literals      │  Destructuring           │
    │                  │  Object literals     │                          │
    │  Creates         │  Individual items    │  Array or Object         │
    │  Example         │  [...arr]            │  [a, ...rest] = arr      │
    └──────────────────┴──────────────────────┴──────────────────────────┘

SIDE BY SIDE EXAMPLES:

    const numbers = [1, 2, 3, 4, 5];

    // SPREAD - Takes array and spreads it out:
    console.log(...numbers);              // 1 2 3 4 5 (individual values)
    const copy = [...numbers];            // Creates new array
    Math.max(...numbers);                 // 5 (spreads into arguments)

    // REST - Takes individual items and collects them:
    const [a, b, ...rest] = numbers;      // rest = [3, 4, 5] (array)
    function sum(...args) { }             // args collects all arguments

🎯 7.4 ADVANCED TRICKS & PATTERNS
───────────────────────────────────────────────────────────────────────────

1) REMOVE DUPLICATES FROM ARRAY:

7) CURRY FUNCTION WITH REST:
   const curry = (fn) => {
       return function curried(...args) {
           if (args.length >= fn.length) {
               return fn(...args);
           }
           return (...moreArgs) => curried(...args, ...moreArgs);
       };
   };
   
   const add = (a, b, c) => a + b + c;
   const curriedAdd = curry(add);
   console.log(curriedAdd(1)(2)(3));  // Output: 6
   console.log(curriedAdd(1, 2)(3));  // Output: 6

ADVANTAGES:
    ✅ Makes code more concise and readable
    ✅ Immutable operations (doesn't change original)
    ✅ Essential for modern React development
    ✅ Flexible function parameters
    ✅ Easy array/object manipulation
    ✅ Better than .concat() or Object.assign()
    ✅ Works with any iterable (arrays, strings, sets, etc.)
    ✅ Helps avoid mutations (functional programming)

DISADVANTAGES:
    ❌ Only creates shallow copies (nested objects share reference)
    ❌ Can be confusing for beginners
    ❌ Performance impact with very large arrays/objects
    ❌ Not supported in old browsers (need transpiler)
    ❌ Same syntax (...) for different purposes can confuse
    ❌ Can make code less readable if overused

COMMON MISTAKES:

    1) Thinking Spread Creates Deep Copy:
       ❌ const obj = { nested: { value: 1 } };
          const copy = { ...obj };  // Shallow! nested is still shared!
       
       ✅ const deepCopy = JSON.parse(JSON.stringify(obj));

    2) Using Rest in Wrong Position:
       ❌ const [...rest, last] = [1, 2, 3];  // SyntaxError!
       ✅ const [first, ...rest] = [1, 2, 3];  // Rest must be last!

    3) Spreading Non-Iterables:
       ❌ const obj = {...123};  // Error! Can't spread number
       ✅ const obj = {...{ a: 1 }};  // Works! Spreading object

    4) Forgetting Performance:
       ❌ // In a loop - creates many copies!
          for (let i = 0; i < 1000; i++) {
              const newArr = [...bigArray];  // Slow!
          }
       
       ✅ // Better: operate on original if no mutation needed
          for (let i = 0; i < 1000; i++) {
              processArray(bigArray);  // Faster!
          }

    5) Wrong Order When Merging:
       const defaults = { theme: 'light', color: 'blue' };
       const user = { theme: 'dark' };
       
       ❌ const config = { ...user, ...defaults };
          // Output: { theme: 'light', color: 'blue' } - defaults override!
       
       ✅ const config = { ...defaults, ...user };
          // Output: { theme: 'dark', color: 'blue' } - user overrides!

                    � SECTION 8: TEMPLATE LITERALS & STRING INTERPOLATION
═══════════════════════════════════════════════════════════════════════════

WHAT IS IT?
    Template literals are a modern way to create strings with variables 
    inside them! They use backticks (`) instead of quotes!
    
    Think of it like filling in blanks in a template:
    "Hello, ___!" becomes "Hello, John!"

WHY USE IT?
    ✅ Much cleaner than string concatenation
    ✅ Can include variables easily
    ✅ Can span multiple lines
    ✅ More readable code
    ✅ No more + + + ... mess!

WHEN TO USE?
    - Building dynamic strings with variables
    - Creating HTML templates
    - Building dynamic URLs
    - Any string with multiple variables

WHERE TO USE?
    - Web development
    - Creating dynamic DOM content
    - API requests
    - Error messages with data
    - HTML templates

───────────────────────────────────────────────────────────────────────────
🎯 8.1 BASIC TEMPLATE LITERALS
───────────────────────────────────────────────────────────────────────────

SYNTAX:
    const message = `Hello, ${variableName}!`;
    
    Notice: Backticks `, not quotes ' or "
    Variables go inside: ${variable}

COMPARISON:

    ❌ OLD WAY (String Concatenation):
    const name = "Alice";
    const age = 25;
    const message = "Hello, " + name + "! You are " + age + " years old.";
    console.log(message);  // Hello, Alice! You are 25 years old.

    ✅ NEW WAY (Template Literals):
    const name = "Alice";
    const age = 25;
    const message = `Hello, ${name}! You are ${age} years old.`;
    console.log(message);  // Hello, Alice! You are 25 years old.

MUCH CLEANER! 🎉

MORE EXAMPLES:

    1) Simple Variable:
       const user = "John";
       console.log(`Welcome, ${user}!`);
       // Output: Welcome, John!

    2) Math Operations:
       const a = 10;
       const b = 20;
       console.log(`${a} + ${b} = ${a + b}`);
       // Output: 10 + 20 = 30

    3) Function Calls:
       function getName() { return "Bob"; }
       console.log(`Hello, ${getName()}!`);
       // Output: Hello, Bob!

    4) Object Properties:
       const user = { name: "Alice", age: 25 };
       console.log(`User: ${user.name}, Age: ${user.age}`);
       // Output: User: Alice, Age: 25

    5) Conditional Logic:
       const age = 20;
       console.log(`You are ${age >= 18 ? "an adult" : "a minor"}`);
       // Output: You are an adult

───────────────────────────────────────────────────────────────────────────
🎯 8.2 MULTI-LINE STRINGS
───────────────────────────────────────────────────────────────────────────

WHAT IS IT?
    Template literals can span multiple lines without any special syntax!

❌ OLD WAY (Messy):
    const text = "Line 1\n" +
                 "Line 2\n" +
                 "Line 3";

✅ NEW WAY (Clean):
    const text = `Line 1
Line 2
Line 3`;

REAL EXAMPLE - HTML Template:

    const user = { name: "John", email: "john@example.com" };

    const htmlTemplate = `
        <div class="card">
            <h2>${user.name}</h2>
            <p>Email: ${user.email}</p>
        </div>
    `;

    console.log(htmlTemplate);
    // Output: Clean HTML with proper formatting!

KID-FRIENDLY ANALOGY:
    Template literals are like Mad Libs 📝 game:
    
    OLD WAY: "Hello" + " " + name + "! Welcome to " + place + "!"
    
    NEW WAY: `Hello ${name}! Welcome to ${place}!`
    
    Instead of cutting up words and gluing them together, you fill in 
    blanks in a pre-made sentence! Much easier! ✨

                    📂 SECTION 9: MODERN ES6+ PATTERNS
═══════════════════════════════════════════════════════════════════════════

WHAT ARE MODERN PATTERNS?
    These are newer ES6+ operators and techniques that make code cleaner!

OPTIONAL CHAINING (?.)
    - Safely access nested properties
    - Returns undefined if property missing
    - Example: user?.address?.city
    - Never throws error if property doesn't exist!

NULLISH COALESCING (??)
    - Provides default values
    - Only cares about null/undefined (not 0 or false!)
    - Example: value ?? "default"
    - Better than || operator for defaults

SHORT CIRCUIT OPERATORS
    - && for conditional execution
    - Returns first falsy or last value
    - || for default values
    - Example: isAdmin && performAction()

REAL WORLD EXAMPLE:

    const user = {
        name: "John",
        address: { city: "NYC" }
    };

    // Optional chaining + Nullish coalescing
    const city = user?.address?.city ?? "Unknown";
    // Result: "NYC"

    const user2 = { name: "Jane" };
    const city2 = user2?.address?.city ?? "Unknown";
    // Result: "Unknown"

    // Short circuit
    const isAdmin = false;
    isAdmin && performAdminAction();  // Doesn't run

    const theme = userTheme || systemTheme || "light";
