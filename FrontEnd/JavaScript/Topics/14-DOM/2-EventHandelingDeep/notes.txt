EVENT OBJECT IN JAVASCRIPT
==========================

WHAT IS AN EVENT OBJECT?
------------------------
The event object is automatically created and passed to event handlers when an event occurs.
It contains all information about the event (what happened, where, when, which element, etc.)

Convention: Usually named 'e', 'evt', or 'event' as the parameter in event handlers.


KEY PROPERTIES
--------------

1. e.target
   - The element that TRIGGERED the event (the actual clicked element)
   - Most commonly used property
   - Example: If you click a <span> inside a <button>, e.target is the <span>

2. e.currentTarget
   - The element that the event listener is ATTACHED to
   - Always the element with addEventListener()
   - Example: Same scenario, e.currentTarget is the <button>

3. e.type
   - Type of event that occurred
   - Returns: "click", "submit", "keydown", "mouseover", etc.

4. e.timeStamp
   - Time when event was created (milliseconds since page load)
   - Useful for performance tracking or double-click prevention

5. e.bubbles
   - Boolean: Does this event bubble up the DOM tree?
   - true for most events (click, keydown), false for focus/blur


MOUSE EVENT PROPERTIES
----------------------

e.clientX, e.clientY
   - Mouse position relative to the viewport (visible browser window)
   
e.pageX, e.pageY
   - Mouse position relative to the entire document (including scroll)

e.screenX, e.screenY
   - Mouse position relative to the entire screen

e.button
   - Which mouse button was pressed
   - 0 = left, 1 = middle, 2 = right

e.altKey, e.ctrlKey, e.shiftKey, e.metaKey
   - Boolean: Was Alt/Ctrl/Shift/Meta(Command) key pressed during click?


KEYBOARD EVENT PROPERTIES
--------------------------

e.key
   - The actual character/key pressed
   - Examples: "a", "A", "Enter", "Escape", "ArrowUp"

e.code
   - Physical key on keyboard (independent of layout)
   - Examples: "KeyA", "Enter", "ArrowUp", "Space"

e.keyCode (DEPRECATED)
   - Numeric code for key (old way, avoid using)

e.altKey, e.ctrlKey, e.shiftKey, e.metaKey
   - Boolean: Was modifier key pressed?


FORM EVENT PROPERTIES
----------------------

For input/change events on form elements:
e.target.value - Current value of input/textarea/select

For submit events:
e.target - The <form> element itself
Can access form data: new FormData(e.target)


CRITICAL METHODS
----------------

1. e.preventDefault()
   - Prevents the default browser behavior
   - Common uses:
     * Stop form submission
     * Prevent link navigation
     * Block context menu
     * Cancel drag-and-drop default
   
   Example:
   form.addEventListener('submit', (e) => {
     e.preventDefault(); // Don't submit, handle with JS
     // custom validation/AJAX
   });

2. e.stopPropagation()
   - Stops the event from bubbling up to parent elements
   - Event won't trigger listeners on ancestor elements
   
   Example:
   childBtn.addEventListener('click', (e) => {
     e.stopPropagation(); // Parent won't receive this click
   });

3. e.stopImmediatePropagation()
   - Like stopPropagation() BUT also prevents OTHER listeners on the SAME element
   - Very rarely needed


EVENT FLOW (IMPORTANT CONCEPT)
-------------------------------

Events occur in 3 phases:
1. CAPTURE phase: Event goes DOWN from window → target
2. TARGET phase: Event reaches the target element
3. BUBBLE phase: Event goes UP from target → window

By default, addEventListener uses BUBBLE phase.
To use capture: addEventListener('click', handler, true)

Example:
<div class="parent">
  <button class="child">Click</button>
</div>

When button clicked:
1. Capture: window → document → body → div → button
2. Target: button
3. Bubble: button → div → body → document → window


e.target vs e.currentTarget EXAMPLE
------------------------------------

<div id="parent">
  <button id="child">Click Me</button>
</div>

document.getElementById('parent').addEventListener('click', (e) => {
  console.log(e.target);        // <button> (what you clicked)
  console.log(e.currentTarget); // <div id="parent"> (where listener is)
  console.log(e.currentTarget === e.target); // false
});

If you click the button:
- e.target = button (actual element clicked)
- e.currentTarget = div (element with the listener)


COMMON PATTERNS
---------------

1. Getting clicked element data:
   button.addEventListener('click', (e) => {
     const id = e.target.dataset.id;
     const text = e.target.textContent;
   });

2. Keyboard shortcuts:
   document.addEventListener('keydown', (e) => {
     if (e.ctrlKey && e.key === 's') {
       e.preventDefault();
       saveDocument();
     }
   });

3. Form validation:
   input.addEventListener('blur', (e) => {
     if (e.target.value.length < 3) {
       e.target.classList.add('error');
     }
   });

4. Mouse tracking:
   document.addEventListener('mousemove', (e) => {
     cursor.style.left = e.clientX + 'px';
     cursor.style.top = e.clientY + 'px';
   });

5. Preventing multiple submissions:
   form.addEventListener('submit', (e) => {
     e.preventDefault();
     e.target.querySelector('button').disabled = true;
     // submit logic
   });


BEST PRACTICES
--------------

1. Always name it clearly: 'e', 'event', or 'evt'
2. Use e.preventDefault() for forms, links, context menus
3. Use e.target for event delegation (see separate notes)
4. Use e.currentTarget when you need the listener's element
5. For keyboard events, prefer e.key over deprecated e.keyCode
6. Check e.target before acting (might not be the element you expect)
7. Remember: e.currentTarget is null in async callbacks (save it first!)


COMMON GOTCHAS
--------------

❌ e.currentTarget in setTimeout:
button.addEventListener('click', (e) => {
  setTimeout(() => {
    console.log(e.currentTarget); // null! (event object is reused)
  }, 1000);
});

✅ Save it first:
button.addEventListener('click', (e) => {
  const btn = e.currentTarget;
  setTimeout(() => {
    console.log(btn); // Works!
  }, 1000);
});

❌ Forgetting preventDefault:
<a href="#" onclick="doSomething()"> // Page will jump to top!

✅ Use preventDefault:
link.addEventListener('click', (e) => {
  e.preventDefault();
  doSomething();
});


INTERVIEW QUESTIONS
-------------------

Q: What's the difference between e.target and e.currentTarget?
A: e.target is the element that triggered the event (actual clicked element).
   e.currentTarget is the element the listener is attached to.

Q: What does e.preventDefault() do?
A: Cancels the default browser behavior for that event (form submit, link click, etc.)

Q: What does e.stopPropagation() do?
A: Stops the event from bubbling up to parent elements.

Q: Can you access the event object in all event handlers?
A: Yes, it's automatically passed as the first parameter to any event handler function.

Q: What happens to the event object after the handler finishes?
A: It's reused by the browser, so properties like e.currentTarget become null in async code.

EVENT DELEGATION
========================================
========================================

WHAT IS EVENT DELEGATION?
--------------------------
Event delegation is a smart technique where instead of adding event listeners to many individual 
elements, you add ONE listener to a parent element and let it handle events from all its children.

SIMPLE ANALOGY:
Think of a classroom with 30 students. Instead of giving each student a walkie-talkie to call you,
you just sit in the room and listen to anyone who raises their hand. Much more efficient!


HOW DOES IT WORK?
-----------------
It relies on EVENT BUBBLING - when you click a child element, the click event "bubbles up" through 
all its parent elements. The parent listener can catch this event and check which child was clicked.


WHY USE EVENT DELEGATION?
--------------------------

1. PERFORMANCE & MEMORY
   - One listener instead of hundreds = less memory usage
   - Faster page initialization
   - Example: 1000 list items = 1 listener, not 1000 listeners

2. WORKS WITH DYNAMIC CONTENT
   - Elements added AFTER page load automatically work
   - No need to attach new listeners when adding elements
   - Perfect for: todo lists, tables, shopping carts

3. CLEANER CODE
   - All related logic in one place
   - Easier to maintain and debug
   - Single source of truth for event handling

4. AUTOMATIC CLEANUP
   - When elements are removed, no need to remove their listeners
   - Prevents memory leaks


THE PROBLEM WITHOUT EVENT DELEGATION
-------------------------------------

Imagine a todo list with 100 items:
- Need to add 100 event listeners
- When adding new todo → must manually add listener
- When deleting todo → should remove listener (or memory leak)
- 100 functions in memory even if most are identical
- Slow when manipulating many elements

CODE EXAMPLE (BAD APPROACH):
----------------------------
// HTML:
// <ul id="todo-list">
//   <li><button class="delete-btn">Delete</button></li>
//   <li><button class="delete-btn">Delete</button></li>
//   <li><button class="delete-btn">Delete</button></li>
// </ul>

// ❌ WITHOUT DELEGATION (inefficient)
const deleteButtons = document.querySelectorAll('.delete-btn');
deleteButtons.forEach(button => {
  button.addEventListener('click', (e) => {
    e.target.closest('li').remove();
  });
});

// Problems:
// 1. If you have 1000 buttons = 1000 event listeners!
// 2. New buttons added later won't work:
const newLi = document.createElement('li');
newLi.innerHTML = '<button class="delete-btn">Delete</button>';
document.getElementById('todo-list').appendChild(newLi);
// ⚠️ This new button won't have a listener! It won't work!


THE SOLUTION WITH EVENT DELEGATION
-----------------------------------

With event delegation:
- Only 1 listener on the parent <ul>
- New todos automatically work (event bubbles up)
- Deleted todos automatically cleanup
- 1 function in memory
- Fast even with 1000s of elements

CODE EXAMPLE (GOOD APPROACH):
-----------------------------
// HTML: (same as above)

// ✅ WITH DELEGATION (efficient)
const todoList = document.getElementById('todo-list');

todoList.addEventListener('click', (e) => {
  // Check if the clicked element is a delete button
  if (e.target.classList.contains('delete-btn')) {
    e.target.closest('li').remove();
  }
});

// Benefits:
// 1. Only 1 listener, no matter how many buttons!
// 2. New buttons automatically work:
const newLi = document.createElement('li');
newLi.innerHTML = '<button class="delete-btn">Delete</button>';
todoList.appendChild(newLi);
// ✅ This new button works automatically! No extra code needed!


HOW TO IDENTIFY WHICH ELEMENT WAS CLICKED
------------------------------------------

The secret is using e.target - it tells you the actual element that was clicked.

Then you check:
1. Is it the type of element you care about?
2. Does it have the right class?
3. Does it match the selector you want?

Common checking methods:
- e.target.classList.contains('class-name') → checks if element has a class
- e.target.matches('.selector') → checks if element matches CSS selector
- e.target.closest('.selector') → finds nearest parent matching selector
- e.target.tagName === 'BUTTON' → checks element type

CODE EXAMPLES:
--------------
const container = document.getElementById('container');

container.addEventListener('click', (e) => {
  
  // Method 1: Using classList.contains()
  if (e.target.classList.contains('delete-btn')) {
    console.log('Delete button clicked!');
  }
  
  // Method 2: Using matches() - more flexible
  if (e.target.matches('.btn-primary')) {
    console.log('Primary button clicked!');
  }
  
  // Method 3: Using matches() with complex selectors
  if (e.target.matches('button[data-action="save"]')) {
    console.log('Save button clicked!');
  }
  
  // Method 4: Using tagName
  if (e.target.tagName === 'BUTTON') {
    console.log('Some button was clicked!');
  }
  
  // Method 5: Using dataset
  if (e.target.dataset.action === 'delete') {
    const id = e.target.dataset.id;
    console.log(`Delete item ${id}`);
  }
});


UNDERSTANDING e.target vs e.currentTarget IN DELEGATION
--------------------------------------------------------

e.target = The ACTUAL element you clicked (child)
e.currentTarget = The element WITH the listener (parent)

Example: Parent <ul> with listener, you click a child <button>
- e.target = <button> (what you clicked)
- e.currentTarget = <ul> (where the listener is)

This is why delegation works - you check e.target to see what was clicked!

CODE EXAMPLE:
-------------
// HTML:
// <ul id="menu">
//   <li><button class="menu-btn">Home</button></li>
//   <li><button class="menu-btn">About</button></li>
//   <li><button class="menu-btn">Contact</button></li>
// </ul>

const menu = document.getElementById('menu');

menu.addEventListener('click', (e) => {
  console.log('e.target:', e.target);           // <button> (what you clicked)
  console.log('e.currentTarget:', e.currentTarget); // <ul> (where listener is)
  
  // This is how delegation works:
  if (e.target.classList.contains('menu-btn')) {
    console.log('Button text:', e.target.textContent);
  }
});


WHEN TO USE closest()
----------------------

Problem: Sometimes you click nested elements inside the target

Example: Button with icon inside
<button class="delete-btn">
  <i class="icon"></i>
  Delete
</button>

If you click the <i>, e.target is the icon, not the button!

Solution: Use closest()
- e.target.closest('.delete-btn') finds the button even if you clicked the icon
- It searches UP the tree from e.target to find matching element
- Returns null if no match found

CODE EXAMPLE:
-------------
// HTML:
// <div id="container">
//   <button class="action-btn">
//     <i class="icon-trash"></i>
//     <span>Delete</span>
//   </button>
// </div>

const container = document.getElementById('container');

// ❌ PROBLEM: This doesn't work if you click icon or span
container.addEventListener('click', (e) => {
  if (e.target.classList.contains('action-btn')) {
    console.log('Button clicked!');
    // ⚠️ This only works if you click the button itself,
    // not the icon or span inside!
  }
});

// ✅ SOLUTION: Use closest() to handle nested elements
container.addEventListener('click', (e) => {
  const button = e.target.closest('.action-btn');
  
  if (button) {
    console.log('Button clicked!'); // Works regardless of what you click!
    console.log('Button text:', button.textContent);
  }
});

// How closest() works:
// 1. Starts at e.target (the icon or span)
// 2. Checks if it matches '.action-btn' → No
// 3. Moves up to parent → checks again
// 4. Finds the <button> → Yes! Returns it
// 5. If no match found up to container → returns null


COMMON USE CASES
----------------

1. TODO LISTS
   - Single listener handles: add, delete, complete, edit buttons
   - New todos automatically work

2. TABLES
   - Handle: sort, edit, delete for all rows
   - Dynamic rows just work

3. NAVIGATION MENUS
   - Single listener for all menu items
   - Works with submenus

4. IMAGE GALLERIES
   - Click any thumbnail to open lightbox
   - New images auto-work

5. FORM DYNAMIC FIELDS
   - Add/remove input fields
   - No listener management needed

6. SHOPPING CARTS
   - Increase/decrease quantity, remove items
   - Cart updates handled centrally

--------------

// Example 1: TODO LIST
// --------------------
const todoList = document.getElementById('todo-list');

todoList.addEventListener('click', (e) => {
  // Handle complete button
  if (e.target.classList.contains('complete-btn')) {
    const li = e.target.closest('li');
    li.classList.toggle('completed');
  }
  
  // Handle delete button
  if (e.target.classList.contains('delete-btn')) {
    const li = e.target.closest('li');
    li.remove();
  }
  
  // Handle edit button
  if (e.target.classList.contains('edit-btn')) {
    const li = e.target.closest('li');
    const text = li.querySelector('.todo-text');
    text.contentEditable = true;
    text.focus();
  }
});

});

    lightbox.style.display = 'block';
  }

MULTIPLE EVENT TYPES WITH DELEGATION
-------------------------------------

You can delegate different event types!

For CLICK events:
- parent.addEventListener('click', handler)
- Check e.target for buttons, links, etc.

For HOVER effects:
- parent.addEventListener('mouseover', handler)
- Check e.target for items you want to highlight

For KEYBOARD events:
- parent.addEventListener('keydown', handler)
- Check e.target for specific inputs

CODE EXAMPLE:
-------------
const container = document.getElementById('container');

// Click events
container.addEventListener('click', (e) => {
  if (e.target.matches('.card')) {
    console.log('Card clicked!');
  }
});

// Hover effects (mouseover + mouseout)
container.addEventListener('mouseover', (e) => {
  if (e.target.matches('.card')) {
    e.target.classList.add('hover');
  }
});

container.addEventListener('mouseout', (e) => {
  if (e.target.matches('.card')) {
    e.target.classList.remove('hover');
  }
});

// Keyboard events (for inputs in container)
container.addEventListener('keydown', (e) => {
  // Enter key on any input
  if (e.target.matches('input') && e.key === 'Enter') {
    console.log('Enter pressed in:', e.target.name);
  }
  
  // Escape key on any textarea
  if (e.target.matches('textarea') && e.key === 'Escape') {
    e.target.blur(); // Remove focus
  }
});


GETTING DATA FROM CLICKED ELEMENTS
-----------------------------------

Use data-* attributes to store information:
<button data-id="123" data-action="delete">Delete</button>

In your handler:
- const id = e.target.dataset.id → "123"
- const action = e.target.dataset.action → "delete"

This makes it easy to know WHAT to do and WITH WHAT data!

CODE EXAMPLE:
-------------
// HTML:
// <ul id="product-list">
//   <li data-id="101" data-category="electronics" data-price="299">
//     <h3>Laptop</h3>
//     <button class="add-to-cart">Add to Cart</button>
//     <button class="view-details">View</button>
//   </li>
//   <li data-id="102" data-category="clothing" data-price="49">
//     <h3>T-Shirt</h3>
//     <button class="add-to-cart">Add to Cart</button>
//     <button class="view-details">View</button>
//   </li>
// </ul>

const productList = document.getElementById('product-list');

productList.addEventListener('click', (e) => {
  // Get the product element (li)
  const product = e.target.closest('li');
  
  if (product) {
    // Extract data from the product
    const id = product.dataset.id;
    const category = product.dataset.category;
    const price = product.dataset.price;
    
    // Add to cart button
    if (e.target.classList.contains('add-to-cart')) {
      console.log(`Adding to cart:`);
      console.log(`ID: ${id}, Category: ${category}, Price: $${price}`);
      addToCart(id, price);
    }
    
    // View details button
    if (e.target.classList.contains('view-details')) {
      console.log(`Viewing product ${id}`);
      showProductDetails(id);
    }
  }
});


PREVENTING DEFAULT BEHAVIOR IN DELEGATION
------------------------------------------

You can still use e.preventDefault() with delegation!

Example: Form submission or link clicks
- Check if e.target is a link or form
- Call e.preventDefault()
- Handle with custom logic

CODE EXAMPLE:
-------------
// Example 1: Smooth scroll for anchor links
const nav = document.querySelector('nav');

nav.addEventListener('click', (e) => {
  // Check if clicked element is an anchor link starting with #
  if (e.target.matches('a[href^="#"]')) {
    e.preventDefault(); // Stop default jump
    
    const targetId = e.target.getAttribute('href').slice(1);
    const targetElement = document.getElementById(targetId);
    
    targetElement.scrollIntoView({ behavior: 'smooth' });
  }
});


// Example 2: Form validation with delegation
const formContainer = document.getElementById('form-container');

formContainer.addEventListener('submit', (e) => {
  // Check if it's one of our forms
  if (e.target.matches('form.validate')) {
    e.preventDefault(); // Stop form submission
    
    const formData = new FormData(e.target);
    const data = Object.fromEntries(formData);
    
    // Validate
    if (data.email && data.email.includes('@')) {
      console.log('Valid! Submitting...', data);
      // Submit via AJAX
    } else {
      console.log('Invalid email!');
    }
  }
});


// Example 3: Prevent context menu on images
const gallery = document.getElementById('gallery');

gallery.addEventListener('contextmenu', (e) => {
  if (e.target.matches('img')) {
    e.preventDefault(); // Block right-click menu on images
    console.log('Right-click disabled on images');
  }
});
- Handle with custom logic

WHEN NOT TO USE EVENT DELEGATION
---------------------------------

1. FOCUS/BLUR EVENTS
   - These don't bubble by default
   - Use 'focusin'/'focusout' instead (they DO bubble)

2. SPECIFIC ELEMENT NEEDS UNIQUE BEHAVIOR
   - If each element has completely different logic
   - Delegation makes code more complex

3. PERFORMANCE-CRITICAL ANIMATIONS
   - Direct listeners might be faster for constant hover effects
   - Delegation adds small overhead for checking e.target

4. PARENT IS TOO FAR AWAY
   - If parent is very high up (like <body> or <document>)
   - Event has to bubble through many elements
   - Can slow down response


BEST PRACTICES
--------------

1. DELEGATE TO NEAREST COMMON PARENT
   - Not too high (not document), not too low
   - Find the container that holds all related elements

2. ALWAYS CHECK IF ELEMENT EXISTS
   - Use if statements before acting
   - e.target might not be what you expect

3. USE MEANINGFUL SELECTORS
   - Classes for delegation: .action-btn, .delete-btn
   - Data attributes: data-action="delete"

4. COMBINE WITH data-* ATTRIBUTES
   - Store IDs, actions, metadata
   - Makes code cleaner and more maintainable

5. USE closest() FOR NESTED ELEMENTS
   - Handles clicks on child elements inside target
   - More reliable than checking e.target directly

6. GROUP RELATED ACTIONS
   - One listener can handle multiple button types
   - Use data-action or different classes to distinguish


COMPARISON: WITH vs WITHOUT DELEGATION
---------------------------------------

WITHOUT DELEGATION:
❌ 1000 buttons = 1000 listeners
❌ ~50KB memory for all listeners
❌ New buttons need manual listener attachment
❌ Deleted buttons need manual listener removal
❌ Slower DOM manipulation
❌ More code to maintain

WITH DELEGATION:
✅ 1000 buttons = 1 listener
✅ ~0.5KB memory
✅ New buttons work automatically
✅ Deleted buttons cleanup automatically
✅ Fast DOM manipulation
✅ Less code, easier maintenance

DELEGATION WITH MULTIPLE ACTIONS
---------------------------------

You can handle many different actions with one listener:

Use data-action attribute:
- data-action="save" → save button
- data-action="delete" → delete button
- data-action="edit" → edit button

In your listener:
1. Check e.target
2. Get data-action value
3. Use switch/if to handle each action
4. All centralized in one place!

CODE EXAMPLE:
-------------
// HTML:
// <div id="panel">
//   <button data-action="save" data-id="123">Save</button>
//   <button data-action="delete" data-id="123">Delete</button>
//   <button data-action="edit" data-id="123">Edit</button>
//   <button data-action="duplicate" data-id="123">Duplicate</button>
//   <button data-action="share" data-id="123">Share</button>
// </div>

const panel = document.getElementById('panel');

panel.addEventListener('click', (e) => {
  const button = e.target.closest('[data-action]');
  
  if (button) {
    const action = button.dataset.action;
    const id = button.dataset.id;
    
    // Handle all actions in one place!
    switch(action) {
      case 'save':
        console.log(`Saving item ${id}...`);
        saveItem(id);
        break;
        
      case 'delete':
        console.log(`Deleting item ${id}...`);
        if (confirm('Are you sure?')) {
          deleteItem(id);
        }
        break;
        
      case 'edit':
        console.log(`Editing item ${id}...`);
        openEditModal(id);
        break;
        
      case 'duplicate':
        console.log(`Duplicating item ${id}...`);
        duplicateItem(id);
        break;
        
      case 'share':
        console.log(`Sharing item ${id}...`);
        shareItem(id);
        break;
        
      default:
        console.log('Unknown action:', action);
    }
  }
});

// Alternative using object mapping (cleaner):
const actions = {
  save: (id) => saveItem(id),
  delete: (id) => confirm('Sure?') && deleteItem(id),
  edit: (id) => openEditModal(id),
  duplicate: (id) => duplicateItem(id),
  share: (id) => shareItem(id)
};

panel.addEventListener('click', (e) => {
  const button = e.target.closest('[data-action]');
  
  if (button) {
    const action = button.dataset.action;
    const id = button.dataset.id;
    
    // Execute the action if it exists
    if (actions[action]) {
      actions[action](id);
    }
  }
});


KEY DIFFERENCES FROM NORMAL EVENTS
-----------------------------------

NORMAL EVENT LISTENER:
- Attached directly to the element you want to listen to
- element.addEventListener('click', handler)
- Only triggers when THAT specific element is clicked
- Need one listener per element

EVENT DELEGATION:
- Attached to a PARENT element
- parent.addEventListener('click', handler)
- Triggers when ANY child is clicked (due to bubbling)
- Check e.target to see which child was clicked
- One listener handles all children


IMPORTANT CONCEPTS TO REMEMBER
-------------------------------

1. EVENT BUBBLING IS THE KEY
   - Without bubbling, delegation won't work
   - Most events bubble (click, keydown, mouseover)
   - Some don't (focus, blur, load)

2. e.target IS YOUR FRIEND
   - Always shows WHAT was clicked
   - Use it to determine which child triggered the event

3. closest() SAVES THE DAY
   - Handles nested elements gracefully
   - Searches up until it finds a match

4. ONE LISTENER = MANY ELEMENTS
   - This is the whole point
   - Performance and convenience combined

INTERVIEW QUESTIONS
-------------------

Q: What is event delegation?
A: A technique where you attach ONE event listener to a parent element instead of multiple 
   listeners to child elements, relying on event bubbling to catch events from children.

Q: Why use event delegation?
A: Better performance (less memory), works with dynamically added elements, easier maintenance,
   and automatic cleanup when elements are removed.

Q: How do you know which element was clicked in event delegation?
A: Check e.target - it points to the actual element that triggered the event.

Q: What's the difference between e.target and e.currentTarget in delegation?
A: e.target is the child element that was clicked. e.currentTarget is the parent element 
   where the listener is attached.

Q: When should you NOT use event delegation?
A: For focus/blur events (use focusin/focusout), when each element needs completely unique 
   behavior, or when the parent is too far up the DOM tree.

Q: What is closest() and why use it in delegation?
A: closest() searches UP from e.target to find the nearest ancestor matching a selector.
   It's useful when you click nested elements inside your target (like clicking an icon 
   inside a button).

Q: Does event delegation work for all events?
A: No. It only works for events that BUBBLE. Most events bubble (click, keydown) but some 
   don't (focus, blur). Use focusin/focusout as alternatives.

Q: What's the performance benefit of event delegation?
A: Instead of 1000 listeners (one per element), you have 1 listener. This saves memory and 
   makes DOM manipulation much faster.

STOP PROPAGATION
========================================
========================================

WHAT IS stopPropagation()?
---------------------------
stopPropagation() is a method on the event object that stops an event from continuing 
its journey through the DOM tree. It prevents the event from reaching parent elements 
(in bubbling phase) or child elements (in capturing phase).


WHY IS IT NEEDED?
-----------------
Without stopPropagation(), events BUBBLE UP through all parent elements. Sometimes you want 
to handle an event at one specific level and prevent parent handlers from also triggering.

Example problem:
- You have a button inside a div
- Both have click listeners
- Click button → BOTH handlers fire (button's, then div's)
- Sometimes you only want the button's handler to run

Solution: Use e.stopPropagation() in the button's handler!


HOW DOES IT WORK?
------------------
Remember the 3 phases of event flow:
1. CAPTURING: window → target (going DOWN)
2. TARGET: reached the target element
3. BUBBLING: target → window (going UP)

stopPropagation() stops the event from continuing to the next phase:
- Called during bubbling → won't reach parent elements
- Called during capturing → won't reach child elements
- Called on target → still triggers all handlers on that element


CODE EXAMPLE: THE PROBLEM
--------------------------
// HTML:
// <div class="parent">
//   <button class="child">Click Me</button>
// </div>

const parent = document.querySelector('.parent');
const child = document.querySelector('.child');

parent.addEventListener('click', () => {
  console.log('Parent clicked!');
});

child.addEventListener('click', () => {
  console.log('Child clicked!');
});

// When you click the button:
// Output:
// "Child clicked!"
// "Parent clicked!"  ← Bubbled up to parent!

// Problem: Sometimes you don't want the parent handler to fire


CODE EXAMPLE: THE SOLUTION
---------------------------
// HTML: (same as above)

const parent = document.querySelector('.parent');
const child = document.querySelector('.child');

parent.addEventListener('click', () => {
  console.log('Parent clicked!');
});

child.addEventListener('click', (e) => {
  e.stopPropagation(); // STOPS BUBBLING!
  console.log('Child clicked!');
});

// When you click the button:
// Output:
// "Child clicked!"
// (That's it! Parent handler never runs!)


VISUAL REPRESENTATION
----------------------
WITHOUT stopPropagation():
Click Button → Child handler runs → Event bubbles up → Parent handler runs

WITH stopPropagation():
Click Button → Child handler runs → stopPropagation() called → Event stops → Parent handler DOESN'T run


WHEN TO USE stopPropagation()
------------------------------

1. NESTED CLICKABLE ELEMENTS
   - Card with a delete button
   - Card click → opens details
   - Button click → deletes card
   - Don't want card to open when deleting!

2. DROPDOWN MENUS
   - Click dropdown item → select it
   - Don't want click to close dropdown AND trigger body click handler

3. MODALS/OVERLAYS
   - Click inside modal → interact with content
   - Click overlay → close modal
   - Don't want clicks inside modal to close it

4. CUSTOM CONTEXT MENUS
   - Prevent default right-click menu
   - Show custom menu
   - Don't want document click handler to interfere

5. NESTED COMPONENTS
   - Parent component has click handler
   - Child component needs independent click handling
   - Prevent parent from reacting to child clicks

stopPropagation() vs stopImmediatePropagation()
------------------------------------------------

TWO SIMILAR BUT DIFFERENT METHODS:

1. e.stopPropagation()
   - Stops event from bubbling to PARENT elements
   - Other listeners on the SAME element still run
   - Most commonly used

2. e.stopImmediatePropagation()
   - Stops event from bubbling to PARENT elements
   - ALSO prevents other listeners on the SAME element from running
   - Rarely needed

CODE EXAMPLE:
-------------
const button = document.querySelector('button');

// Three listeners on the SAME button
button.addEventListener('click', (e) => {
  console.log('Handler 1');
  e.stopPropagation(); // Only stops bubbling to parents
});

button.addEventListener('click', (e) => {
  console.log('Handler 2'); // This STILL runs!
});

button.addEventListener('click', (e) => {
  console.log('Handler 3'); // This STILL runs!
});

// Output when button clicked:
// "Handler 1"
// "Handler 2"
// "Handler 3"
// (All three handlers on button run, but parent handlers don't)


// Now with stopImmediatePropagation():
button.addEventListener('click', (e) => {
  console.log('Handler 1');
  e.stopImmediatePropagation(); // Stops EVERYTHING!
});

button.addEventListener('click', (e) => {
  console.log('Handler 2'); // This NEVER runs!
});

button.addEventListener('click', (e) => {
  console.log('Handler 3'); // This NEVER runs!
});

// Output when button clicked:
// "Handler 1"
// (That's it! Other handlers on same button don't run, and neither do parent handlers)


WHEN TO USE stopImmediatePropagation()
---------------------------------------

Very rare! Only when you have multiple handlers on the same element and need to prevent 
later handlers from running.

Example use case:
- Plugin system where multiple plugins add handlers
- First handler determines event should be completely stopped
- Don't want any other handlers (even on same element) to run


stopPropagation() vs preventDefault()
--------------------------------------

DIFFERENT PURPOSES - DON'T CONFUSE THEM!

e.stopPropagation()
- Controls EVENT FLOW through DOM tree
- Stops bubbling/capturing to other elements
- Doesn't affect the default browser action

e.preventDefault()
- Prevents DEFAULT BROWSER BEHAVIOR
- Stops: form submission, link navigation, context menu, etc.
- Doesn't affect event flow through DOM

COMPARISON TABLE:
-----------------
| Method               | Stops Bubbling? | Prevents Default Action? |
|---------------------|-----------------|-------------------------|
| stopPropagation()    | YES            | NO                      |
| preventDefault()     | NO             | YES                     |
| Both can be used together!                                      |

CODE EXAMPLE:
-------------
// Prevent link navigation AND stop bubbling
document.querySelector('a').addEventListener('click', (e) => {
  e.preventDefault();       // Don't navigate to href
  e.stopPropagation();      // Don't bubble to parent
  
  console.log('Link clicked, but nothing happens!');
});


// Form inside a clickable div
const form = document.querySelector('form');
const container = document.querySelector('.container');

// Container has a click handler
container.addEventListener('click', () => {
  console.log('Container clicked!');
});

// Form submit handler
form.addEventListener('submit', (e) => {
  e.preventDefault();      // Don't submit form (page reload)
  e.stopPropagation();     // Don't trigger container click
  
  console.log('Form submitted via AJAX');
  // Handle form submission...
});


WHEN NOT TO USE stopPropagation()
----------------------------------

1. DON'T USE BY DEFAULT
   - Only use when you have a specific problem
   - Event bubbling is usually helpful, not harmful
   - Overusing it makes debugging harder

2. EVENT DELEGATION NEEDS BUBBLING
   - If parent uses delegation, stopPropagation() breaks it
   - Parent won't receive events from children
   - Be careful with delegation patterns

3. ANALYTICS/TRACKING
   - Document-level click tracking won't work
   - Global event handlers won't receive events
   - Can break third-party scripts

4. TESTING/DEBUGGING
   - Makes it harder to track event flow
   - Can hide bugs in event handlers
   - Use sparingly and document why

  if (e.target.classList.contains('add-to-cart')) {
    e.stopPropagation(); // DON'T navigate to product page!
    
    console.log(`Adding product ${productId} to cart...`);
    addToCart(productId);
    
    // Show feedback
    e.target.textContent = '✓ Added';
    setTimeout(() => {
      e.target.textContent = 'Add to Cart';
    }, 2000);
  }
  
  // Quick View button
  else if (e.target.classList.contains('quick-view')) {
    e.stopPropagation(); // DON'T navigate to product page!
    
    console.log(`Opening quick view for ${productId}...`);
    openQuickView(productId);
  }
  
  // Favorite button
  else if (e.target.classList.contains('favorite')) {
    e.stopPropagation(); // DON'T navigate to product page!
    
    console.log(`Toggling favorite for ${productId}...`);
    e.target.textContent = e.target.textContent === '♡' ? '♥' : '♡';
    toggleFavorite(productId);
  }
  
  // Click anywhere else on card → navigate to product page
  else {
    console.log(`Navigating to product ${productId}...`);
    window.location.href = `/products/${productId}`;
  }
});

// Why stopPropagation() is CRITICAL here:
// Without it, clicking any button would:
// 1. Execute the button's action (add to cart, etc.)
// 2. Bubble up to card
// 3. Trigger card's click handler
// 4. Navigate to product page (WRONG!)
// 
// With stopPropagation():
// 1. Execute button's action
// 2. Stop event (no bubbling)
// 3. Card's handler doesn't run
// 4. Stay on current page (CORRECT!)


INTERVIEW QUESTIONS
-------------------

Q: What does stopPropagation() do?
A: It stops an event from bubbling up to parent elements (or capturing down to children).
   Prevents handlers on ancestor elements from being triggered.

Q: What's the difference between stopPropagation() and preventDefault()?
A: stopPropagation() stops event flow through the DOM (bubbling/capturing).
   preventDefault() stops the browser's default action (form submit, link click, etc.).
   They serve different purposes and can be used together.

Q: What's the difference between stopPropagation() and stopImmediatePropagation()?
A: stopPropagation() stops bubbling but allows other handlers on the same element to run.
   stopImmediatePropagation() stops bubbling AND prevents other handlers on the same 
   element from running. stopImmediatePropagation() is rarely needed.

Q: When should you use stopPropagation()?
A: When you have nested clickable elements and don't want the parent's handler to trigger
   when clicking the child. Common cases: buttons inside cards, dropdown menus, modals,
   nested components.

Q: When should you NOT use stopPropagation()?
A: Don't use it by default or "just in case". Only use when needed. Overuse can break
   event delegation, analytics tracking, and make debugging harder.

Q: Can you use both preventDefault() and stopPropagation()?
A: Yes! They're independent. preventDefault() stops default browser behavior, while
   stopPropagation() stops event flow. Often used together on links or forms.

Q: Does stopPropagation() affect event delegation?
A: Yes! If a child calls stopPropagation(), the parent's delegated handler won't receive
   that event. Be careful when mixing delegation with stopPropagation().

WHAT ARE FORM EVENTS?
----------------------
Form events are special events that fire when users interact with form elements:
- <input>, <textarea>, <select>, <form>, <button>

These events help you:
- Capture user input in real-time
- Validate data before submission
- Provide instant feedback
- Control form behavior
- Create interactive forms


THE 5 ESSENTIAL FORM EVENTS
----------------------------

1. submit   - Form submission (prevent default, validate, send data)
2. input    - Value changes (EVERY keystroke, paste, etc.)
3. change   - Value changes AND loses focus (after editing done)
4. focus    - Element receives focus (clicked/tabbed into)
5. blur     - Element loses focus (clicked away/tabbed out)


1. SUBMIT EVENT 📤
------------------

When it fires:
- User clicks submit button
- User presses Enter in a text input (inside form)
- form.submit() is called programmatically

Target: <form> element (NOT the button!)

Common uses:
- Validate all fields before submitting
- Prevent default submission (handle with AJAX)
- Show loading indicator
- Disable submit button to prevent double submission

CODE EXAMPLES:
--------------
// Basic form submission prevention
const form = document.querySelector('form');

form.addEventListener('submit', (e) => {
  e.preventDefault(); // CRITICAL: Stop the form from submitting!
  console.log('Form submitted!');
});


// Real-world example: Form validation
const loginForm = document.getElementById('login-form');

loginForm.addEventListener('submit', (e) => {
  e.preventDefault(); // Stop default submission
  
  // Get form data
  const formData = new FormData(e.target);
  const email = formData.get('email');
  const password = formData.get('password');
  
  // Validate
  if (!email || !email.includes('@')) {
    alert('Please enter a valid email');
    return;
  }
  
  if (password.length < 6) {
    alert('Password must be at least 6 characters');
    return;
  }
  
  // Disable submit button
  const submitBtn = e.target.querySelector('button[type="submit"]');
  submitBtn.disabled = true;
  submitBtn.textContent = 'Submitting...';
  
  // Submit via AJAX
  fetch('/api/login', {
    method: 'POST',
    body: JSON.stringify({ email, password }),
    headers: { 'Content-Type': 'application/json' }
  })
  .then(response => response.json())
  .then(data => {
    console.log('Success:', data);
    window.location.href = '/dashboard';
  })
  .catch(error => {
    console.error('Error:', error);
    submitBtn.disabled = false;
    submitBtn.textContent = 'Login';
  });
});


// Getting all form values at once
form.addEventListener('submit', (e) => {
  e.preventDefault();
  
  const formData = new FormData(e.target);
  const data = Object.fromEntries(formData);
  
  console.log(data);
  // { username: 'john', email: 'john@example.com', age: '25' }
});

FORM EVENT DELEGATION
----------------------

Problem: focus and blur don't bubble!
Solution: Use 'focusin' and 'focusout' (they DO bubble)

CODE EXAMPLE:
-------------
// ❌ This won't work (focus doesn't bubble)
form.addEventListener('focus', (e) => {
  // Won't catch focus on inputs inside form
});

// ✅ Use focusin instead (it bubbles!)
const form = document.querySelector('form');

form.addEventListener('focusin', (e) => {
  if (e.target.matches('input, textarea')) {
    console.log('Field focused:', e.target.name);
    e.target.style.backgroundColor = '#ffffcc';
  }
});

form.addEventListener('focusout', (e) => {
  if (e.target.matches('input, textarea')) {
    console.log('Field blurred:', e.target.name);
    e.target.style.backgroundColor = 'white';
  }
});

BEST PRACTICES
--------------

1. ALWAYS preventDefault() on submit
   - Prevents page reload
   - Allows custom handling

2. Use INPUT for real-time feedback
   - Search suggestions
   - Character counters
   - Live validation

3. Use CHANGE for final validation
   - After user finishes typing
   - Saves unnecessary checks

4. Use FOCUS to help users
   - Show hints and examples
   - Highlight active field

5. Use BLUR for validation
   - Validate after editing done
   - Format values (add $ sign)

6. Clear errors on focus
   - Better UX
   - Gives user a fresh start

7. Disable submit during processing
   - Prevents double submission
   - Shows loading state

8. Use focusin/focusout for delegation
   - They bubble (focus/blur don't)
   - Cleaner code

INTERVIEW QUESTIONS
-------------------

Q: What's the difference between 'input' and 'change' events?
A: 'input' fires on EVERY value change (every keystroke). 'change' fires only when the 
   value changes AND the element loses focus. Use 'input' for real-time feedback, 'change' 
   for final validation.

Q: Why do we use e.preventDefault() in form submit handlers?
A: To stop the form from submitting normally (which reloads the page). This allows us to 
   handle validation and submission with JavaScript (often via AJAX).

Q: What's the difference between 'focus' and 'focusin'?
A: 'focus' fires when an element receives focus but does NOT bubble. 'focusin' fires when 
   an element receives focus and DOES bubble, making it useful for event delegation.

Q: When should you validate a form field?
A: Use multiple strategies: 
   - 'input' for live feedback (password strength, character count)
   - 'blur' for validation after editing (email format, required fields)
   - 'submit' for final validation before sending

Q: How do you get all form values at once?
A: Use FormData: 
   const formData = new FormData(form);
   const data = Object.fromEntries(formData);

Q: How do you prevent double form submission?
A: Disable the submit button after first click:
   submitBtn.disabled = true;
   submitBtn.textContent = 'Submitting...';

Q: Why clear error messages on focus?
A: Better UX - it gives users a fresh start when they begin editing, making the form 
   feel more responsive and less punishing.
